# 方案管理规范

> 本文档定义项目设计文档的管理规则，确保 plan 目录始终反映系统真实状态。

---

## 1. 目录结构

```
plan/
├── 00-方案管理规范.md              # 本文件
├── 01-整体架构设计.md              # 系统概述、技术栈、目录结构、部署架构
├── 02-数据库设计.md                # 完整表结构、关系、主键策略
├── 03-工作流引擎设计.md            # 步骤定义、状态机、LLM 调用、BERTScore
├── 04-RDU指标体系设计.md           # 指标分类、风险信号、匹配逻辑
├── 05-API接口设计.md               # 完整 REST API 文档
├── 06-前端交互设计.md              # 路由、状态机、轮询、工作流可视化
├── 07-并发控制与日志设计.md         # Semaphore、httpx pool、结构化日志
├── 08-系统配置页面设计.md           # 模型/指标/风险信号配置页面
├── 09-部署方案.md                   # 生产环境部署架构、配置、运维
├── CHANGELOG.md                    # 变更记录
└── data/                           # 数据文件（Excel、JSON 等）
```

## 2. 文档编号规则

| 编号范围 | 说明 |
|---------|------|
| 00 | 方案管理规范（本文件） |
| 01-07 | 已实现模块的设计文档 |
| 08+ | 草案 / 待实现模块的设计文档 |

## 3. 文档状态标识

每个设计文档标题下方标注状态：

- `[已实现]` - 对应功能已编码、已测试、已上线
- `[草案]` - 设计方案已确认但尚未实现
- `[已废弃]` - 被新方案替代，保留供参考

## 4. 变更流程

```
开发者提出方案（临时 spec 文件）
       ↓
用户审核确认
       ↓
编码实现
       ↓
测试通过
       ↓
更新 plan/ 目录下的对应文档
       ↓
更新 CHANGELOG.md
```

### 4.1 临时方案

- 存放位置：Qoder 工作目录中的 spec 文件
- 用途：设计讨论、方案评审
- 生命周期：确认后合并到正式文档，否则丢弃

### 4.2 正式方案

- 存放位置：`plan/` 目录
- 触发更新条件：用户确认 + 测试通过
- 更新操作：修改对应文档 + 更新 CHANGELOG.md

## 5. CHANGELOG 维护规则

每次更新 plan 目录时，在 `CHANGELOG.md` 顶部追加一条记录：

```markdown
## vX.Y (YYYY-MM-DD)

- [文档编号] 变更说明
```

## 6. Qoder Skill 配合

项目配置了 `plan-manager` Skill，自动执行以下行为：

1. **临时方案**不直接写入 plan 目录
2. 功能实现 + 测试通过后，主动提醒用户："是否需要更新 plan 目录下的设计文档？"
3. 更新时在对应章节追加变更标注：`<!-- Updated: YYYY-MM-DD 变更说明 -->`
4. 同步更新 CHANGELOG.md

## 7. 数据文件管理

- 数据文件（Excel、JSON、CSV 等）统一存放在 `plan/data/` 子目录
- 不与设计文档混放
- 文件命名应具有自解释性
