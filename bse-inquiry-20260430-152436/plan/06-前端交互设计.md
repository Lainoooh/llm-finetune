## 5. 前端状态机

### 5.1 消息卡片（Chat 中的 workflow 消息）

| 任务状态 | 图标 | 颜色 | 文案 |
|---------|------|------|------|
| running | Loader2 (旋转) | 蓝色 `text-[#004EA2]` | "正在对 XX 执行深度分析..." |
| paused | PauseCircle | 橙色 `text-orange-500` | "流程暂停，等待专家确认" |
| completed | CheckCircle2 | 绿色 `text-green-500` | "年报审查深度分析已完成" |
| failed | XCircle | 红色 `text-red-500` | "审查任务执行失败" |

### 5.2 工作流步骤圆点

| 状态 | 圆点边框 | 图标 | 标题颜色 |
|------|---------|------|---------|
| needsAction | `border-orange-500` | PauseCircle 橙色 | 橙色 |
| showAsCompleted | `border-green-500` | Check 绿色 | gray-900 |
| isCurrent (auto) | `border-[#004EA2]` | 蓝色脉动点 | `text-[#004EA2]` |
| isFailed | `border-red-500` | X 红色 | 红色 |
| pending | `border-gray-200` | 空 | gray-400 |

### 5.3 关键判断逻辑

```javascript
const needsAction = isWaitNode && activeTask.status === 'paused'
                    && activeTask.current_step === index;
const showAsCompleted = isCompleted && !needsAction;
```

**优先级**：`needsAction` > `isCompleted`，防止 manual 步骤在 DB status=completed 但任务仍 paused 时显示为已完成。

## 6. 轮询机制

### 6.1 轮询参数

| 参数 | 值 |
|------|-----|
| 初始延迟 | 1.5s |
| 轮询间隔 | 2s |
| 错误重试间隔 | 3s |

### 6.2 轮询停止条件

- 任务状态为 `completed` 或 `failed`
- 离开 chat 视图（`currentViewRef` 检测）
- 组件卸载（useEffect cleanup）

### 6.3 失败处理

轮询检测到 `task.status === 'failed'` 时：
- 停止轮询
- 注入失败消息到聊天流（含失败步骤名称和错误详情）

## 7. 暂停时自动打开确认面板

当点击暂停状态的任务卡片时：

```javascript
// 仅 manual_risk 和 manual_item 类型联动打开
if (isPausedManual) {
  handleOpenConfirmPanel(pausedStepDef.type.replace('manual_', ''), msg.taskId);
}
```

确认面板（Modal）展示：
- Step 3 (manual_risk)：风险信号列表，可勾选触发状态
- Step 5 (manual_item)：问询事项列表，可编辑内容

**统一模式**：所有 purpose 共享同一个 model_name + endpoint_url，仅 Prompt 不同
**独立模式**：每个 purpose 独立配置 model_name + endpoint_url + Prompt

|---------|---------|------|

| risk_signal | 风险信号 | Step 2 Phase 2 |
| inquiry_logic | 问询逻辑 | Step 4 Phase 1 |
