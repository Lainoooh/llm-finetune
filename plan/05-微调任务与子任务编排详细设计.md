# 微调任务与子任务编排详细设计

> 状态：[草案]  
> 创建时间：2026-05-21  
> 最后更新：2026-05-21

## 1. 模块目标

微调任务模块负责将一个业务目标拆解为多个可执行训练子任务，并管理每个子任务的配置、运行、日志、产物和评测结果。

系统要支持的核心模式：

- 一个任务对应一个目标模型阶段。
- 一个任务下可以挂多个子任务。
- 一个子任务执行一次完整 LLaMA-Factory 微调训练。
- 一个子任务绑定一个服务器对象，使用该对象配置的全部 GPU。
- 多个子任务可以并行启动，但必须通过 GPU 资源锁避免冲突。

## 2. 任务创建

### 2.1 输入字段

| 字段 | 说明 |
|---|---|
| 任务名称 | 如 `customer_service_v1` |
| 目标模型名 | 输出模型或 Adapter 的业务名称 |
| 基座模型 | 如 `Qwen/Qwen3-8B` 或远程路径 |
| 描述 | 任务目的 |
| 默认输出目录模板 | 可选 |

### 2.2 状态

| 状态 | 说明 |
|---|---|
| `draft` | 任务已创建，无运行子任务 |
| `waiting` | 有子任务但未启动 |
| `running` | 至少一个子任务运行中 |
| `succeeded` | 全部结束且存在成功子任务 |
| `failed` | 全部结束且全部失败 |
| `paused` | 用户暂停 |

## 3. 子任务创建

### 3.1 输入字段

| 字段 | 说明 |
|---|---|
| 子任务名称 | 如 `rank32_lr5e-5` |
| 服务器对象 | 从服务器资源池选择 |
| GPU | 默认使用服务器对象配置的 GPU IDs |
| 基模路径 | 可继承任务基模，也可覆盖 |
| 输出目录 | 默认由任务和子任务 ID 生成 |
| 训练集 | 数据集名称 |
| 评测集 | 数据集名称 |
| 训练参数 | 可视化表单或 YAML |

### 3.2 子任务状态

| 状态 | 说明 |
|---|---|
| `draft` | 已配置但未启动 |
| `queued` | 等待执行或等待资源 |
| `preparing` | 同步配置、检查目录 |
| `running` | 训练中 |
| `evaluating` | 评测中 |
| `succeeded` | 训练完成 |
| `failed` | 训练失败 |
| `stopped` | 用户停止 |

## 4. 子任务配置页设计

当前 `SubtaskPage` 已有六个 tab，建议保留并增强。

### 4.1 基础配置

目标：

- 选择服务器对象。
- 展示服务器资源快照。
- 配置子任务名称、GPU、基模路径、输出目录。

规则：

- GPU 输入默认只读，来自服务器对象。
- 如果允许手动修改 GPU，必须二次校验资源锁。
- 输出目录默认：

```text
${server.workDir}/tasks/${task.id}/subtasks/${subtask.id}
```

### 4.2 数据集

目标：

- 管理训练集和评测集。
- 上传或选择数据文件。
- 生成 LLaMA-Factory `dataset_info.json`。
- 同步到远程工作目录。

第一阶段：

- 本地选择数据集名称。
- 生成 `dataset_info.json` 文本。
- 通过执行器写入远程文件。

### 4.3 训练参数

目标：

- 支持常用参数可视化编辑。
- 支持 YAML 高级编辑。
- 生成 `train.yaml`。

关键字段：

- `stage`
- `do_train`
- `finetuning_type`
- `lora_rank`
- `lora_alpha`
- `learning_rate`
- `num_train_epochs`
- `per_device_train_batch_size`
- `save_steps`
- `cutoff_len`
- `bf16`
- `template`
- `dataset`
- `eval_dataset`
- `output_dir`

### 4.4 远程目录

目标：

- 展示子任务工作目录。
- 刷新远程目录树。
- 支持下载重要文件。

需要远程命令：

```bash
find "$SUBTASK_DIR" -maxdepth 3 -printf '%y %s %p\n'
```

### 4.5 训练日志

目标：

- 实时查看训练 stdout/stderr。
- 支持下载日志。
- 支持从日志解析 step、loss、lr、grad_norm。

日志来源：

- 启动训练命令的 stdout/stderr。
- 远程 `train.log` 文件。
- LLaMA-Factory 输出。

### 4.6 测试评测

目标：

- 执行 Adapter 加载测试。
- 执行业务评测脚本。
- 解析指标结果。

输出：

- 评测状态。
- 指标分数。
- 评测日志。
- 评测结果文件路径。

## 5. 启动训练流程

```text
用户点击启动 / 重试
  -> 后端读取子任务配置
  -> 校验服务器对象在线
  -> 校验 GPU 未被锁定
  -> 创建 ExecutionRun
  -> 锁定 GPU
  -> 生成远程目录
  -> 写入 dataset_info.json
  -> 写入 train.yaml
  -> 写入 run.sh
  -> 远程执行训练命令
  -> 实时写入日志
  -> 解析训练指标
  -> 训练结束释放 GPU 锁
  -> 更新子任务状态
```

## 6. 并行启动任务

当前 `TaskDetailPage.startAll()` 只是把状态改为 running。目标实现：

1. 找到任务下状态为 `draft`、`failed`、`stopped` 的子任务。
2. 对每个子任务校验绑定服务器对象。
3. 尝试获取 GPU 锁。
4. 获取锁成功的子任务进入 `queued` 或 `running`。
5. 获取锁失败的子任务保持 `waiting` 并返回冲突原因。
6. 前端展示启动结果汇总。

并行启动不等于同时无限制启动。它应是“批量尝试启动”，由资源锁控制实际并发。

## 7. 停止训练

停止策略：

- 记录 run pid 或进程标识。
- 优先发送温和停止信号。
- 超时后强制停止。
- 停止后释放资源锁。

在 Jupyter 临时通道下，停止命令可通过：

```bash
pkill -f "<subtask_id>"
```

更稳妥的方式是启动时写入 pid 文件：

```bash
echo $! > "$SUBTASK_DIR/run.pid"
```

停止时读取 pid 文件。

## 8. 输出产物

每个子任务输出目录应包含：

```text
subtask_dir/
  train.yaml
  dataset_info.json
  run.sh
  run.pid
  logs/
    stdout.log
    stderr.log
    train.log
  outputs/
    adapter/
    checkpoints/
  eval/
    eval.yaml
    result.json
    eval.log
```

## 9. 综合对比

ComparePage 后续应从真实数据生成：

- 每个子任务最终 loss。
- 每个子任务评测分。
- 训练耗时。
- GPU 配置。
- 关键训练参数。
- 输出目录。

综合对比状态：

- 有 running 子任务时不可最终比较。
- 可允许预览已完成子任务。
- 支持标记推荐子任务。
