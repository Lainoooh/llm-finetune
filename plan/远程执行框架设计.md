# 远程执行框架设计

## 1. 架构概述

### 1.1 设计目标

当前平台需要通过远程服务器执行探测、脚本下发、训练启动、日志读取、评测等操作。架构设计目标：

- **统一接口**：前端只关心统一 JSON 请求和响应，不关心服务器使用 Jupyter 还是 SSH
- **队列管理**：队列锁、超时、marker、输出归一化全部在通用执行框架层
- **断线重连**：Transport 异常后自动关闭连接，下一次请求自动重连
- **可扩展性**：新增 Docker API、K8s、Slurm 时，只新增 Transport，不重写执行框架

### 1.2 分层架构

```text
Frontend / API
  - 发送统一 JSON 请求
  - 接收统一 JSON 响应

Business Services
  - server_service: 服务器探测
  - subtask_service: 训练启动/停止/状态同步
  - script_service: 脚本模板管理

RemoteExecutorFactory
  - 根据 ServerProfile.access_type 选择执行入口

QueuedRemoteSession
  - 长连接生命周期管理
  - 队列锁（asyncio.Lock）
  - 超时控制
  - Marker 机制和结束判断
  - stdout/stderr 归一化
  - 失败 reset 和断线重连

RemoteTransport
  - JupyterTransport: Jupyter Terminal WebSocket
  - SshTransport: SSH 连接
  - Future: DockerTransport / K8sTransport / SlurmTransport
```

**职责分离：**
- **Transport**：只负责 IO（连接、发送、接收、关闭）
- **QueuedRemoteSession**：负责队列、marker、超时、重连
- **Business Services**：负责业务规则、资源锁、状态流转

## 2. Transport 层

### 2.1 Transport 协议

Transport 只负责 IO，不负责脚本包装、marker、队列和业务状态。

```python
class RemoteTransport:
    @property
    def key(self) -> str:
        """Transport 唯一标识，用于会话缓存"""
        ...
    
    async def connect(self) -> None:
        """建立连接"""
        ...
    
    async def send(self, payload: str) -> None:
        """发送数据到远程 stdin"""
        ...
    
    async def recv(self) -> RemoteFrame:
        """接收远程输出帧"""
        ...
    
    async def close(self) -> None:
        """关闭连接"""
        ...
```

**统一输出帧：**

```python
@dataclass
class RemoteFrame:
    kind: str  # "stdout" | "stderr"
    content: str
```

### 2.2 JupyterTransport

Jupyter Terminal WebSocket 适配器。

**实现：**

- `connect()`：
  - `POST /api/terminals` 创建 terminal
  - 建立 `/terminals/websocket/{name}` WebSocket 连接
  
- `send(payload)`：
  - 发送 `["stdin", payload]` 到 WebSocket
  
- `recv()`：
  - 读取 WebSocket frame
  - 将 `["stdout", "..."]` / `["stderr", "..."]` 转为 `RemoteFrame`
  
- `close()`：
  - 关闭 WebSocket
  - 尝试删除 terminal（`DELETE /api/terminals/{name}`）

**关键代码：**

```python
class JupyterTransport:
    def __init__(self, endpoint: JupyterEndpoint):
        self.endpoint = endpoint
        self.terminal_name = None
        self.ws = None
    
    @property
    def key(self) -> str:
        return f"jupyter:{self.endpoint.base_url}"
    
    async def connect(self):
        # 创建 terminal
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                f"{self.endpoint.base_url}/api/terminals",
                params={"token": self.endpoint.token}
            )
            self.terminal_name = resp.json()["name"]
        
        # 建立 WebSocket
        ws_url = f"{self.endpoint.ws_url}/terminals/websocket/{self.terminal_name}"
        self.ws = await websockets.connect(ws_url)
    
    async def send(self, payload: str):
        await self.ws.send(json.dumps(["stdin", payload]))
    
    async def recv(self) -> RemoteFrame:
        msg = await self.ws.recv()
        kind, content = json.loads(msg)
        return RemoteFrame(kind=kind, content=content)
    
    async def close(self):
        if self.ws:
            await self.ws.close()
        # 删除 terminal（可选）
```

### 2.3 SshTransport

SSH 连接适配器（未来实现）。

**实现：**

- `connect()`：
  - 使用 `asyncssh.connect()` 建立连接
  - 创建长期 shell process
  
- `send(payload)`：
  - 写入 shell stdin
  
- `recv()`：
  - 从 stdout/stderr 读取内容并转为 `RemoteFrame`
  
- `close()`：
  - 关闭 shell process 和 SSH connection

**注意：** SSH 不单独实现队列、marker、超时和重连，这些统一由 `QueuedRemoteSession` 处理。

## 3. QueuedRemoteSession

### 3.1 核心职责

`QueuedRemoteSession` 持有一个 Transport，并统一实现：

- **队列锁**：`asyncio.Lock` 串行执行命令
- **连接管理**：`ensure_connected()` 自动连接和重连
- **Marker 机制**：在脚本末尾添加唯一 marker，检测命令完成
- **超时控制**：超时后关闭 Transport
- **输出归一化**：清理 ANSI 转义序列，提取 JSON 输出
- **错误处理**：Transport 异常后关闭连接，下一次请求自动重连

### 3.2 执行流程

```text
run_script(script, timeout_ms)
  ↓
  acquire lock (串行队列)
  ↓
  ensure_connected()
  ↓
  marker = generate_unique_marker()
  ↓
  payload = inject_marker(script, marker)
  ↓
  transport.send(payload)
  ↓
  loop:
    frame = transport.recv()
    collect stdout/stderr
    if marker found in output:
      return RemoteExecutionResult
  ↓
  timeout:
    reset transport
    raise TimeoutError
```

### 3.3 Marker 机制

**简化方案（当前实现）：**

不使用 base64 + heredoc + 临时文件包装，直接发送脚本并在末尾添加 marker。

```python
def _inject_marker(self, script: str, marker: str) -> str:
    """在脚本末尾（heredoc 之外）添加结束标记"""
    return script.rstrip() + f'\necho "{marker}"\n'
```

**为什么简化：**
- Jupyter Terminal 的交互式提示符会打断复杂的多行命令
- 原子脚本（Python heredoc）可以一次性发送，无需包装
- Marker 只需在脚本末尾添加，无需捕获退出码

**JSON 提取：**

```python
def _extract_json(self, output: str) -> str:
    """从输出中提取 JSON（在 __JSON_START__ 和 __JSON_END__ 之间）"""
    cleaned = clean_terminal_output(output)
    start_marker = "__JSON_START__"
    end_marker = "__JSON_END__"
    
    # 使用 rfind 查找最后一次出现（真正的输出，而不是输入回显）
    start_idx = cleaned.rfind(start_marker)
    end_idx = cleaned.rfind(end_marker)
    
    if start_idx != -1 and end_idx != -1 and start_idx < end_idx:
        json_str = cleaned[start_idx + len(start_marker):end_idx].strip()
        return json_str
    
    return cleaned.strip()
```

### 3.4 关键代码

```python
class QueuedRemoteSession:
    def __init__(self, transport: RemoteTransport):
        self.transport = transport
        self.lock = asyncio.Lock()
        self.connected = False
    
    async def ensure_connected(self):
        if not self.connected:
            await self.transport.connect()
            self.connected = True
    
    async def run_script(self, script: str, timeout_ms: int) -> RemoteExecutionResult:
        async with self.lock:
            try:
                await self.ensure_connected()
                
                marker = f"__LLMFT_MARKER_{uuid.uuid4().hex}__"
                payload = self._inject_marker(script, marker)
                
                await self.transport.send(payload)
                
                raw_output = ""
                start_time = time.time()
                
                while True:
                    if (time.time() - start_time) * 1000 > timeout_ms:
                        await self._reset()
                        raise TimeoutError(f"Script execution timeout after {timeout_ms}ms")
                    
                    frame = await asyncio.wait_for(
                        self.transport.recv(),
                        timeout=(timeout_ms - (time.time() - start_time) * 1000) / 1000
                    )
                    
                    raw_output += frame.content
                    
                    if marker in raw_output:
                        stdout = self._extract_json(raw_output)
                        return RemoteExecutionResult(
                            stdout=stdout,
                            stderr="",
                            exit_code=0,
                            raw_output=raw_output
                        )
            
            except Exception as e:
                await self._reset()
                raise
    
    async def _reset(self):
        """重置连接状态"""
        try:
            await self.transport.close()
        except Exception:
            pass
        self.connected = False
```

## 4. 两层队列设计

系统里必须区分两种队列，它们解决的问题不同。

### 4.1 业务任务队列（持久化）

业务任务队列记录在数据库中，对应 `ExecutionRun`。它是"系统要做什么"的事实来源。

**适用对象：**
- 服务器探测
- 工作目录检查
- 配置同步
- 训练启动
- 训练停止
- 日志读取任务
- 评测启动
- 评测状态检查

**特点：**
- 持久化，可查
- 服务重启后可恢复或标记为异常
- 有明确业务状态
- 与 UI 状态绑定

**数据模型：**

```python
class ExecutionRun:
    id: int  # 雪花算法生成的内部 ID
    run_code: str  # 对外展示编号（可选）
    run_type: str  # server_probe / train_start / train_stop / log_collect / eval_start
    target_type: str  # server / subtask / task
    target_id: int  # 目标内部存储 ID
    server_profile_id: int  # 使用的服务器对象
    status: str  # queued / running / succeeded / failed / timeout / cancelled
    script_key: str  # 使用的脚本模板
    script_version: int  # 脚本版本
    rendered_script: str  # 实际渲染后的脚本，便于审计
    timeout_ms: int  # 超时
    exit_code: int  # 退出码
    stdout: str  # 标准输出
    stderr: str  # 错误输出
    error_message: str  # 错误信息
    created_at: datetime
    started_at: datetime
    finished_at: datetime
```

### 4.2 远程会话队列（内存）

远程会话队列存在于 `QueuedRemoteSession` 内部，对应一个 Transport 连接。

它是"如何把命令送到远程容器"的传输队列。

**特点：**
- 每个远程访问端点一个队列
- FIFO 串行发送命令
- 每条命令有唯一结束标记
- 会话断开后当前命令和队列失败
- 不持久化，不跨 session generation 迁移

**会话缓存 key：**
- Jupyter：`jupyter:{base_url}`
- SSH：`ssh:{user}@{host}:{port}`

同一个 key 共享一个队列；不同 key 队列互相独立。

### 4.3 为什么训练不应长期占用远程会话队列

如果直接在 WebSocket 中执行：

```bash
llamafactory-cli train train.yaml
```

这个命令会持续数小时，导致：
- 队列无法执行其他命令
- 无法刷新目录
- 无法停止训练
- WebSocket 断开时难以判断训练是否仍在跑

**正确方式：**

1. 队列只执行"启动训练后台进程"的短命令
2. 训练进程在远程容器后台运行
3. 训练日志写入远程文件
4. 后端通过短命令定期读取日志增量和状态文件

```text
队列命令 A: 写入 run.sh
队列命令 B: nohup bash run.sh > logs/stdout.log 2>&1 & echo $! > run.pid
队列命令 C: tail 增量读取 logs/stdout.log
队列命令 D: 检查 run.pid 和 status.json
```

## 5. 训练任务执行流程

### 5.1 远程目录结构

每个子任务远程目录：

```text
subtask_dir/
  train.yaml              # 训练配置
  dataset_info.json       # 数据集信息
  run.sh                  # 启动脚本
  run.pid                 # 进程 PID
  status.json             # 状态文件
  logs/
    stdout.log            # 标准输出
    train.log             # 训练日志
  outputs/                # 模型输出
  eval/                   # 评测结果
```

### 5.2 启动脚本（run.sh）

```bash
#!/usr/bin/env bash
set -euo pipefail

cd "__SUBTASK_DIR__"
mkdir -p logs outputs eval

write_status() {
  python3 - "$1" "$2" <<'PY'
import json, sys, time
status, code = sys.argv[1], sys.argv[2]
payload = {
  "status": status,
  "exit_code": None if code == "" else int(code),
  "updated_at": time.time()
}
open("status.json", "w").write(json.dumps(payload, ensure_ascii=False))
PY
}

write_status running ""

export CUDA_VISIBLE_DEVICES="__GPU_IDS__"
set +e
llamafactory-cli train train.yaml 2>&1 | tee logs/train.log
code=${PIPESTATUS[0]}
set -e

if [ "$code" -eq 0 ]; then
  write_status succeeded "$code"
else
  write_status failed "$code"
fi

exit "$code"
```

### 5.3 启动命令

```bash
cd "__SUBTASK_DIR__"
nohup bash run.sh >> logs/stdout.log 2>&1 &
echo $! > run.pid
```

这样训练进程和 WebSocket 生命周期解耦。

### 5.4 状态读取

使用 `subtask.read_status` 脚本读取：

```python
payload = {
    "pid": None,
    "pid_alive": False,
    "status": "unknown",
    "exit_code": None,
}

if os.path.exists("run.pid"):
    pid = int(open("run.pid").read().strip())
    payload["pid"] = pid
    payload["pid_alive"] = pid_alive(pid)

if os.path.exists("status.json"):
    data = json.load(open("status.json"))
    payload["status"] = data.get("status", "unknown")
    payload["exit_code"] = data.get("exit_code")
elif payload["pid_alive"]:
    payload["status"] = "running"
```

### 5.5 日志采集

使用 `subtask.read_log_since` 脚本增量读取：

```python
log_path = os.path.join(SUBTASK_DIR, LOG_FILE)
offset = int(OFFSET)

if os.path.exists(log_path):
    size = os.path.getsize(log_path)
    if offset > size:
        offset = 0
    with open(log_path, "rb") as f:
        f.seek(offset)
        data = f.read(256 * 1024)  # 最多读取 256KB
        result = {
            "offset": offset,
            "next_offset": offset + len(data),
            "content_b64": base64.b64encode(data).decode()
        }
```

后端维护每个 run 的日志偏移量，定期读取增量。

## 6. 后台 Worker

### 6.1 scheduler

**职责：**
- 扫描 `execution_runs.status=queued`
- 根据资源锁和服务器状态决定是否执行
- 调用对应 service 执行任务

**运行频率：** 每 1-3 秒

### 6.2 log_collector

**职责：**
- 扫描 running 的 train/eval run
- 根据日志偏移读取远程日志增量
- 写入 `execution_logs`
- 解析 metrics（loss、lr、step 等）

**运行频率：** 每 2-5 秒

### 6.3 status_poller

**职责：**
- 扫描 running 的 train/eval run
- 读取远程 `status.json` 和 `run.pid`
- 更新 run/subtask 状态
- 释放 GPU 锁

**运行频率：** 每 3-10 秒

### 6.4 cleanup_worker

**职责：**
- 清理超时的 remote command
- 标记长期无心跳的 run
- 清理过期临时 terminal

**运行频率：** 每 60 秒

## 8. 关键状态流

### 8.1 服务器探测

```text
POST /api/servers/:id/probe
  ↓
  create ExecutionRun(server_probe)
  ↓
  render script server.probe_hardware
  ↓
  RemoteExecutor.run_script (短命令)
  ↓
  parse JSON output
  ↓
  update RuntimeEnvironmentSnapshot
  ↓
  update ServerProfile
  ↓
  return snapshot
```

### 8.2 启动训练

```text
POST /api/subtasks/:id/start
  ↓
  validate subtask config
  ↓
  acquire ResourceLock (GPU)
  ↓
  create ExecutionRun(train_start)
  ↓
  render sync scripts
  ↓
  write train.yaml / dataset_info.json / run.sh
  ↓
  execute start_background command
  ↓
  mark subtask running
  ↓
  log_collector / status_poller take over
```

### 8.3 停止训练

```text
POST /api/subtasks/:id/stop
  ↓
  read run.pid
  ↓
  kill pid gracefully (SIGTERM)
  ↓
  poll process (wait 5s)
  ↓
  force kill if needed (SIGKILL)
  ↓
  mark stopped
  ↓
  release ResourceLock
```

### 8.4 日志读取

```text
log_collector (background worker)
  ↓
  scan running train/eval runs
  ↓
  for each run:
    read log offset from execution_log_offsets
    ↓
    execute subtask.read_log_since
    ↓
    decode base64 content
    ↓
    write to execution_logs
    ↓
    parse metrics (loss, lr, step)
    ↓
    update offset
```

## 9. 工厂设计

业务层调用统一入口：

```python
executor = get_executor_for_server(server)
result = await executor.run_script(script, timeout_ms)
```

工厂内部：

```python
def get_executor_for_server(server: ServerProfile) -> QueuedRemoteSession:
    if server.access_type == "jupyter":
        endpoint = JupyterEndpoint(
            base_url=server.jupyter_base_url,
            token=server.jupyter_token
        )
        transport = JupyterTransport(endpoint)
    elif server.access_type == "ssh":
        transport = SshTransport(
            host=server.host,
            port=server.ssh_port,
            user=server.user,
            password=server.password,
            ssh_key=server.ssh_key
        )
    else:
        raise ValueError(f"Unknown access_type: {server.access_type}")
    
    # 会话缓存（同一个 key 共享队列）
    session_key = transport.key
    if session_key not in _session_cache:
        _session_cache[session_key] = QueuedRemoteSession(transport)
    
    return _session_cache[session_key]
```

### 10.3 探测任务拆分

探测任务包含两个互不冲突的子结果：

- `hardware`：宿主机执行，创建工作目录，探测显卡、驱动、磁盘和目录权限
- `finetuneEnv`：进入微调工具容器探测 Python、PyTorch、Transformers 和微调工具版本

前端点击后按钮保持 `探测中`，直到两个子结果都进入 `succeeded` 或 `failed` 才恢复。

页面按子结果独立渲染：
- 硬件先成功就先展示硬件信息
- 如果容器不存在，只在微调环境和微调工具版本处显示红色错误

## 11. 约束

- **不拆分 API**：不创建 `/api/jupyter/...` 和 `/api/ssh/...`
- **统一接口**：前端不根据连接方式调用不同业务接口
- **不重复实现**：不在 JupyterTransport 和 SshTransport 中重复实现队列、marker、超时
- **统一执行框架**：训练启动等长任务仍通过统一执行框架投递远程脚本
