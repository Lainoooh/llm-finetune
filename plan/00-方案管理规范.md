## 3. 状态标识

每个设计文档标题下方标注状态：

- `[草案]`：基于当前需求和代码分析形成，等待确认。
- `[已确认]`：用户确认可作为实现依据。
- `[部分实现]`：已有部分代码落地，仍有待补齐内容。
- `[已实现]`：对应功能完成编码和验证。
- `[已废弃]`：被新方案替代，保留供追溯。

## 4. 变更规则

1. 需求或架构发生变化时，优先更新对应编号文档。
2. 跨模块变化需要同步更新 `CHANGELOG.md`。
3. 临时插件、过渡方案需要明确生命周期，避免和最终架构混淆。
4. 设计文档应反映系统真实方向，不只记录当前 mock 页面。

## 5. 当前背景

当前 `llm-finetune` 是一个 React + Vite 前端原型，主要页面已经覆盖：

- 总览
- 服务器管理
- 微调训练任务
- 任务详情与子任务列表
- 子任务配置
- 综合对比

下一阶段目标是从纯前端 mock 走向可运行系统：通过临时 Jupyter Terminal 通道连接 LLaMA-Factory 容器，完成服务器环境探测、远程命令执行、训练任务启动、日志读取和评测结果回传。
