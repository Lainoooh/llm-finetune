# 系统配置页面设计 [草案]

## 1. 需求概述

将现有"模型配置"单页升级为完整的**系统配置中心**，包含三个配置模块：

| 模块 | 状态 | 核心功能 |
|------|------|----------|
| 模型配置 | 增强 | 新增并发数设置（统一/独立模式分别控制） |
| 指标集配置 | 新建 | 112 个 RDU 标准指标的 CRUD、分类 Tab 导航、分类调整 |
| 风险信号配置 | 新建 | 71 个风险信号的 CRUD、分类 Tab 导航、关联指标编辑 |

**关键设计原则**：
- 分类独立建表 `rdu_categories`，指标和风险信号均通过 `category_id` 关联
- 主题 → 一级分类 两级层次，通过 `level` + `parent_id` 自引用实现
- 指标/风险信号配置页共享相同的 Tab 导航模式：顶部主题选择 → 一级分类 Tab 标签页 → 列表

## 2. 整体架构

### 2.1 页面结构

```
currentView === 'chat'   → 左侧：会话列表     |  右侧：ChatPage
currentView === 'config' → 左侧：配置导航菜单  |  右侧：SystemConfigPage
                                                     ├── ModelConfigPage（增强）
                                                     ├── MetricsConfigPage（新建）
                                                     └── RiskSignalsConfigPage（新建）
```

### 2.2 路由改造

**现状**：hash 路由支持 `['chat', 'model-config', 'metrics', 'risk-signals']` 四个值

**目标**：收敛为 `['chat', 'config']` 两个值，系统配置内部子导航用组件状态 `configTab` 管理

```
hash 路由:  chat | config
                     |
              configTab 状态:  models | metrics | risk-signals
```

### 2.3 侧边栏条件渲染

- `currentView === 'chat'` → 显示会话列表（当前已有）
- `currentView === 'config'` → 显示配置导航菜单，包含三个菜单项：
  - 模型配置（对应 `configTab='models'`）
  - 指标集配置（对应 `configTab='metrics'`）
  - 风险信号配置（对应 `configTab='risk-signals'`）

## 3. 数据库变更

### 3.1 新建 `rdu_categories` 表

```sql
CREATE TABLE IF NOT EXISTS rdu_categories (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,
    code        TEXT UNIQUE,            -- 可选编码，如 'PERF_TOTAL'
    level       INTEGER NOT NULL DEFAULT 0,  -- 0=主题, 1=一级分类
    parent_id   INTEGER DEFAULT NULL REFERENCES rdu_categories(id),
    sort_order  INTEGER DEFAULT 0,
    description TEXT,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_rdu_categories_parent ON rdu_categories(parent_id);
CREATE INDEX IF NOT EXISTS idx_rdu_categories_level ON rdu_categories(level);
```

**初始数据**：

| id | name | level | parent_id | sort_order | 说明 |
|----|------|-------|-----------|------------|------|
| 1  | 关于经营业绩 | 0 | NULL | 0 | 主题（当前唯一） |
| 2  | 整体业绩 | 1 | 1 | 1 | 一级分类 |
| 3  | 分业务（产品） | 1 | 1 | 2 | 一级分类 |
| 4  | 分季度 | 1 | 1 | 3 | 一级分类 |
| 5  | 分区域 | 1 | 1 | 4 | 一级分类 |
| 6  | 分子公司 | 1 | 1 | 5 | 一级分类 |

**与现有数据的兼容性**：

现有 `rdu_metrics_standard` 和 `rdu_risk_signals` 表中 `category_id` 的值为 1-5，
分别对应：1=整体业绩, 2=分业务, 3=分季度, 4=分区域, 5=分子公司。

引入 `rdu_categories` 表后，主题"关于经营业绩"占用 id=1，原有一级分类 ID 需要整体迁移：

```
原 category_id=1（整体业绩）   → 新 category_id=2
原 category_id=2（分业务）     → 新 category_id=3
原 category_id=3（分季度）     → 新 category_id=4
原 category_id=4（分区域）     → 新 category_id=5
原 category_id=5（分子公司）   → 新 category_id=6
```

**迁移方案**：

需要同时更新三个地方：
1. `init.sql` — 修改 INSERT 语句中所有 `category_id` 值（+1）
2. `database.py` `_run_migrations()` — 增加迁移逻辑（处理已存在数据库的升级）
3. `rdu_categories` 初始数据 INSERT

```sql
-- 迁移脚本（在 _run_migrations 中执行，仅在 rdu_categories 表不存在时）
-- Step 1: 创建 rdu_categories 表
-- Step 2: 插入分类数据
INSERT OR IGNORE INTO rdu_categories (id, name, level, parent_id, sort_order) VALUES
    (1, '关于经营业绩', 0, NULL, 0),
    (2, '整体业绩', 1, 1, 1),
    (3, '分业务（产品）', 1, 1, 2),
    (4, '分季度', 1, 1, 3),
    (5, '分区域', 1, 1, 4),
    (6, '分子公司', 1, 1, 5);
-- Step 3: 迁移现有数据（从大到小更新，避免冲突）
UPDATE rdu_metrics_standard SET category_id = category_id + 1 WHERE category_id BETWEEN 1 AND 5;
UPDATE rdu_risk_signals SET category_id = category_id + 1 WHERE category_id BETWEEN 1 AND 5;
```

### 3.2 `models` 表新增 `concurrency` 字段

```sql
ALTER TABLE models ADD COLUMN concurrency INTEGER DEFAULT 1;
```

**并发数配置规则**：

| 模式 | 行为 |
|------|------|
| **统一模式** | 在父模型上设置 `concurrency` 值，保存时同步写入所有 5 个子模型 |
| **独立模式** | 每个子模型各自设置 `concurrency` 值，互不影响 |

**与现有环境变量的关系**：

当前代码通过 `LLM_TASK_CONCURRENCY` 环境变量（默认值 1）控制任务级 Semaphore。
引入 `concurrency` 字段后：

```python
# 获取并发数的优先级：
# 1. 子模型自身的 concurrency 字段（若 > 0）
# 2. 父模型的 concurrency 字段（若 > 0）
# 3. 环境变量 LLM_TASK_CONCURRENCY（兜底）
def get_model_concurrency(model: dict) -> int:
    if model.get('concurrency') and model['concurrency'] > 0:
        return model['concurrency']
    if model.get('parent_model_id'):
        parent = ModelRepo.get_by_id(model['parent_model_id'])
        if parent and parent.get('concurrency') and parent['concurrency'] > 0:
            return parent['concurrency']
    return int(os.getenv('LLM_TASK_CONCURRENCY', '1'))
```

### 3.3 ER 关系变更（新增部分）

```
rdu_categories (新表)
    ├─ 1:N → rdu_categories (自引用: parent_id)
    ├─ 1:N → rdu_metrics_standard (category_id)
    └─ 1:N → rdu_risk_signals (category_id)

models (增强)
    └─ 新字段: concurrency INTEGER
```

## 4. 后端 API 设计

### 4.1 分类管理 — `routers/categories.py`（新建）

| 方法 | 端点 | 描述 | 请求/响应 |
|------|------|------|-----------|
| GET | `/api/categories` | 获取完整分类树 | 响应：嵌套 JSON，主题包含 children |
| GET | `/api/categories?level=0` | 仅获取主题列表 | 响应：平铺列表 |
| GET | `/api/categories?parent_id=1` | 获取指定主题下的一级分类 | 响应：平铺列表 |

**交互流程**：

1. **进入页面**：调用 `GET /api/categories` 获取分类树
2. **主题选择**：下拉框选择主题（当前仅"关于经营业绩"），触发加载该主题下的一级分类
3. **Tab 切换**：点击一级分类 Tab，触发 `GET /api/rdu/metrics?category_id={tab_category_id}`
4. **搜索**：关键词实时过滤当前 Tab 下的指标列表（前端过滤或带 `keyword` 参数请求）
5. **新增**：弹出模态框，填写指标名称、代码、选择分类（下拉框）
6. **编辑**：弹出模态框，可修改名称、代码、分类（调整分类后自动切换到目标 Tab）
7. **删除**：删除前确认，若有风险信号引用则提示无法删除并列出引用信号

**分类调整操作**：

在指标编辑模态框中，分类选择是一个下拉框（列出所有一级分类）。
修改分类后保存，调用 `PUT /api/rdu/metrics/{id}` 更新 `category_id`。
保存成功后：
- 若目标分类与当前 Tab 不同，自动切换到目标分类 Tab
- 刷新列表

## 8. 数据流示意

### 8.1 指标分类调整流程

```
用户点击指标「编辑」
    ↓
弹出编辑模态框（预填当前数据）
    ↓
用户修改分类下拉框：整体业绩 → 分季度
    ↓
点击保存
    ↓
前端调用 PUT /api/rdu/metrics/{id}  body: { category_id: 4, metric_name: ..., metric_code: ... }
    ↓
后端更新 rdu_metrics_standard SET category_id = 4 WHERE id = ?
    ↓
返回成功
    ↓
前端自动切换到「分季度」Tab，刷新列表
```

### 8.2 风险信号关联指标编辑流程

```
用户点击风险信号「编辑」
    ↓
弹出编辑模态框，加载当前 metric_codes（展示为 Tag 列表）
    ↓
用户在搜索框搜索"毛利率"
    ↓
前端从已缓存的全量指标列表中过滤匹配项，展示下拉
    ↓
用户点击选中 → 新增 Tag；点击 × → 移除 Tag
    ↓
点击保存
    ↓
前端调用 PUT /api/rdu-risks/{id}  body: { risk_signal: ..., category_id: ..., metric_codes: [...] }
    ↓
后端更新 rdu_risk_signals SET metric_codes = ? WHERE id = ?
    ↓
返回成功，前端刷新列表
```

### 8.3 模型并发数保存流程

```
用户在模型编辑弹窗修改并发数
    ↓
统一模式: 设置并发数 = 3
    ↓
前端构造 payload: { ..., concurrency: 3, is_unified: true, ... }
    ↓
POST /api/models/batch
    ↓
后端：
  1. 父模型 concurrency = 3
  2. 5 个子模型 concurrency = 3（同步）
    ↓
workflow_engine 执行时：
  model = ModelRepo.get_by_purpose(purpose)
  concurrency = get_model_concurrency(model)  # → 3
  semaphore = asyncio.Semaphore(concurrency)
```
