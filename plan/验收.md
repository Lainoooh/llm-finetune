# 功能验收清单

本文档作为后续前后端研发、自测试和 bug 修复的唯一验收基线。后续实现必须逐项对齐本文档，任何页面按钮、表格数据、统计数据、日志数据不得再停留在 mock 或只改前端状态的阶段。

## 0. 当前问题确认

- 当前开发数据库使用 SQLite。
- SQLite 文件必须放在项目根目录 `data/llm_finetune.db`，即与 `backend/` 同级，不允许放在 `backend/data/`。
- 所有数据库表的 `id` 字段为内部存储 ID，使用雪花算法生成，数据库类型为 `BIGINT`，Python 类型按 `int` 处理，前端不展示、不透传、不作为 URL 参数。
- 对外展示和接口路径使用业务 ID，例如 `server_code`、`task_code`、`subtask_code`、`script_key`、`run_code`，不得把数据库内部 `id` 暴露给前端。
- 当前前端仍存在大量 mock 数据来源：`src/data/mockData.js`、局部数组、局部 `setState` 伪更新、`alert("功能开发中")`。这些都必须在后续实现中清零。
- 当前已初步接入后端的范围只有服务器列表和服务器连通性探测；任务、子任务、训练日志、Loss 曲线、评测、远程目录、报告导出、脚本配置管理等仍未完整接入真实接口。

## 1. 全局验收准则

| 编号 | 验收项 | 验收标准 |
| --- | --- | --- |
| G-01 | 去 mock | 运行时页面不得从 `src/data/mockData.js` 读取业务数据；该文件只能删除，或仅保留在测试 fixture 目录中。 |
| G-02 | 按钮真实可用 | 页面所有按钮必须绑定真实接口或明确的禁用状态；不得出现无业务效果的 `console.log`、`alert("开发中")`、纯前端状态模拟。 |
| G-03 | 数据持久化 | 新增、编辑、删除、启动、停止、重试、保存配置、脚本修改等动作刷新页面后结果仍存在。 |
| G-04 | 加载态 | 所有异步按钮必须有 loading/disabled 状态，避免重复提交。 |
| G-05 | 错误态 | 接口失败必须展示明确错误信息，并保留原有数据状态，不得静默失败。 |
| G-06 | 空状态 | 列表无数据、筛选无结果、日志为空、目录为空时必须有可理解的空状态。 |
| G-07 | 权限与危险操作 | 删除、停止训练、执行远程脚本、批量操作必须二次确认，并记录执行日志。 |
| G-08 | 内部 ID 隔离 | API 响应不得包含数据库内部 `id`；前端代码不得依赖 `id` 为 long。 |
| G-09 | 可自测试 | 每个后端接口有 pytest；每个关键页面流有前端或 e2e 测试；远程 Jupyter 交互支持 fake executor 测试。 |
| G-10 | 端口约定 | 前端开发端口 `30000`，后端开发端口 `30001`，Vite `/api` 代理到后端。 |

## 2. 数据库与后端基础验收

| 编号 | 验收项 | 验收标准 |
| --- | --- | --- |
| DB-01 | SQLite 位置 | 默认数据库为 `sqlite:///./data/llm_finetune.db`，启动后自动创建 `data/` 目录。 |
| DB-02 | Git 忽略 | `data/` 被 `.gitignore` 忽略，数据库文件不进入版本库。 |
| DB-03 | 雪花 ID | 所有表主键 `id` 为 `BIGINT`，默认值由雪花算法生成。 |
| DB-04 | 业务编码 | 服务器、任务、子任务、执行记录、脚本模板都有稳定业务编码字段，并加唯一索引。 |
| DB-05 | 审计字段 | 核心表包含 `created_at`、`updated_at`；执行类表包含 `started_at`、`finished_at`、`status`、`error_message`。 |
| DB-06 | 迁移策略 | 开发期允许自动建表；进入稳定开发后补 Alembic 迁移，不允许手工改库。 |
| DB-07 | 启动种子 | 首次启动可初始化默认 Jupyter 服务器和内置脚本模板，但不得覆盖用户已修改数据。 |
