## 1. 系统概述

北交所年报审查系统是一个基于 LLM 的智能年报分析平台，用于自动审查北交所上市公司的年度报告，识别风险信号并生成问询函。

### 1.1 核心功能
- 年报指标提取（JSON 输入 / PDF 解析）
- RDU（Risk Data Utility）风险信号检测（2 阶段 LLM + BERTScore）
- 7 阶段工作流自动化处理（5 auto + 2 manual）
- 人工审核与决策介入（风险信号确认、问询事项确认）
- 问询函自动生成

### 1.2 技术栈
- **前端**: React + Vite + TailwindCSS + Lucide Icons
- **后端**: Python FastAPI + SQLite (WAL)
- **LLM**: 多模型支持（统一/独立模式），默认 Qwen3-32B / Qwen3-8B（阿里云 DashScope）
- **HTTP 客户端**: httpx（连接池 + 异步）
- **并发控制**: asyncio.Semaphore（2 层：请求级 + 任务级）
- **日志**: python-json-logger（JSON + Console 双格式）
- **认证**: JWT Bearer Token

## 3. 核心模块概览

### 3.1 用户认证模块
- JWT Token 认证，过期时间 24 小时
- 用户名/密码登录（bcrypt 哈希）
- Token 存储在 localStorage，请求自动附加

### 3.2 对话管理模块
- 支持多会话（类似 ChatGPT 侧边栏）
- 每个会话包含多个任务
- 消息持久化存储，支持 text/workflow 类型

### 3.3 任务处理模块
- 任务创建和状态管理（pending/running/paused/completed/failed）
- 7 阶段工作流（详见 [03-工作流引擎设计.md](./03-工作流引擎设计.md)）：

| 步骤 | 名称 | 类型 |
|------|------|------|
| 0 | 年报上传和审查 | auto |
| 1 | 指标提取 | auto |
| 2 | RDU风险信号分析 | auto |
| 3 | RDU风险信号触发判断 | manual_risk |
| 4 | 问询事项生成 | auto |
| 5 | 问询事项确认 | manual_item |
| 6 | 起草正式问询函 | auto |

### 3.4 模型管理模块
- 父子模型体系：1 个父模型 → 5 个子模型（按 purpose 分）
- 统一模式：所有子模型共享同一配置
- 独立模式：每个子模型独立配置
- 5 个 purpose：risk_judgment, risk_signal, inquiry_logic, inquiry_item, common

### 3.5 LLM 服务模块
- httpx 异步连接池（max_connections=20, max_keepalive=10）
- 2 层 Semaphore 并发控制（详见 [07-并发控制与日志设计.md](./07-并发控制与日志设计.md)）
- 统一的 API 调用封装（超时 180s，重试机制）

### 3.6 RDU 指标体系
- **rdu_metrics_standard**: 112 项标准指标定义
- **rdu_risk_signals**: 71 项风险信号定义
- **rdu_metric_values**: 年报扫描提取的指标值
- 详见 [04-RDU指标体系设计.md](./04-RDU指标体系设计.md)

### 3.7 日志模块
- JSON + Console 双格式输出
- ContextVar（task_id, conversation_id）自动传播
- RotatingFileHandler（10MB/5 backups）
- 详见 [07-并发控制与日志设计.md](./07-并发控制与日志设计.md)

## 4. 部署架构

### 4.1 开发环境
- 前端: `http://localhost:30000` (Vite Dev Server)
- 后端: `http://localhost:30001` (FastAPI + uvicorn --reload)
- Vite 代理: `/api` → `http://localhost:30001`

### 4.2 启动命令
```bash
# 后端
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 30001 --reload

# 前端
cd frontend
npx vite --port 30000
```

### 4.3 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VITE_API_BASE` | `''` | 前端 API 地址（开发用 Vite 代理） |
| `LLM_MAX_CONCURRENT_REQUESTS` | `5` | LLM 请求级并发数 |
| `LLM_TASK_CONCURRENCY` | `1` | LLM 密集步骤的任务级并发数 |

## 6. 关键设计决策

### 6.1 SQLite + WAL 模式
- 轻量级，无需额外部署
- WAL 模式支持并发读写
- 适合中小规模应用场景

### 6.2 Repository 模式
- 数据访问逻辑与业务逻辑分离
- 统一使用 `with get_db() as conn:` 上下文管理器

### 6.3 前端状态管理
- React Hooks（useState, useEffect, useCallback, useRef）
- Hash 路由（chat / model-config / metrics / risk-signals）
- 2s 轮询 + 视图感知停止 + 状态终止

### 6.4 2 层并发控制
- 请求级 Semaphore 限制全局 LLM 调用数
- 任务级 Semaphore 限制同时执行的 LLM 密集步骤数
