## 4. 部署流程

### 4.1 一键部署（推荐）

```bash
# 完整部署（构建前端 + 打包 + 上传 + 远程部署）
./scripts/build.sh --push

# 仅后端变更时（跳过前端构建，快速部署）
./scripts/build.sh --skip-frontend --push
```

`--push` 会自动完成：构建 → 打包 → 上传（ssh+cat 管道） → 远程解压 → 执行 `deploy.sh`。

> **sshpass**：如果本地安装了 `sshpass`，会使用 `deploy.conf` 中的密码自动登录；否则回退到 SSH 密钥认证（需提前配置）。macOS 安装：`brew install sshpass` 或 `brew install esolitos/ipa/sshpass`。

### 4.2 本地打包详解

```bash
# 仅打包，不上传
./scripts/build.sh
./scripts/build.sh --skip-frontend
```

`build.sh` 执行流程：
1. 构建前端 `npm run build`（生成 `dist/`，`--skip-frontend` 时跳过）
2. 用 `tar` 打包项目，**排除**：`node_modules`、`frontend/src`、`data/`、`venv/`、`logs/`、`uploads/`、`__pycache__`、`.git`
3. macOS 自动添加 `--no-mac-metadata --no-xattrs`，避免服务器解压时出现 xattr 警告
4. 输出到 `release/bse-inquiry-<时间戳>.tar.gz`（约 177K）

### 4.3 手动部署（备选方案）

不使用 `--push` 时，可手动上传执行：

```bash
# 上传
cat release/bse-inquiry-<VERSION>.tar.gz | ssh root@36.133.115.87 "cat > /tmp/bse-inquiry-<VERSION>.tar.gz"

# 服务器上执行
ssh root@36.133.115.87
cd /tmp
mkdir -p bse-inquiry-<VERSION>
tar -xzf bse-inquiry-<VERSION>.tar.gz -C bse-inquiry-<VERSION>
cd bse-inquiry-<VERSION>
bash scripts/deploy.sh
```

### 4.4 deploy.sh 执行流程

1. **准备目录** — `mkdir -p $DEPLOY_DIR/{data,backend/logs,backend/uploads}`
2. **备份后端代码** — `mv backend/app → backend/app_<时间戳>`（仅替换 app/ 子目录）
3. **放入新代码** — `cp -r app/ → backend/app`，复制 `requirements.txt`
4. **首次部署** — 复制 `.env` 模板（已有则跳过）
5. **备份前端** — `mv frontend → frontend_<时间戳>` + 放入新 frontend
6. **同步文档** — 直接覆盖 `plan/`、`scripts/`
7. **Nginx** — 渲染模板配置 → `nginx -t` 测试 → reload（兼容 systemd 和 `nginx -s reload`）
8. **后端服务** — 进容器安装依赖（`docker exec pip install`）+ 重启 uvicorn（`docker exec pkill`），不操作容器本身
9. **健康检查** — curl 验证后端 API 和前端页面

### 4.5 部署选项

```bash
bash scripts/deploy.sh              # 完整部署（前端 + 后端）
bash scripts/deploy.sh --backend    # 仅更新后端
bash scripts/deploy.sh --frontend   # 仅更新前端
```

## 5. 服务配置

### 5.1 Nginx

文件位置：`/etc/nginx/conf.d/bse.conf`

关键配置：
- `listen {{NGINX_PORT}}` — 对外服务端口（模板变量，deploy.sh 渲染）
- `client_max_body_size 200M` — 允许上传大文件（年报 PDF）
- `root {{DEPLOY_DIR}}/frontend/dist` — 前端静态文件
- `location /api/ → proxy_pass http://127.0.0.1:{{BACKEND_PORT}}` — API 反代
- `proxy_read_timeout 300s` — LLM 长推理超时 5 分钟
- `try_files ... /index.html` — SPA 路由回退
- `gzip on` — 静态资源压缩

当前实际值：`listen 30006`，`proxy_pass http://127.0.0.1:30008`，`root /home/admin/annual-report-inquiry/frontend/dist`

### 5.2 后端 Docker 容器

**设计理念**：容器 = 运行环境（等同于一台配好的服务器）。deploy.sh 只通过 `docker exec` 进容器操作服务，不操作容器本身。

容器名：`annual-report-inquiry`

#### 5.2.1 首次环境初始化（一次性操作）

容器创建是基础设施操作，只需执行一次：

```bash
docker create \
  --name annual-report-inquiry \
  --network host --gpus all --restart unless-stopped \
  -v /home/admin/annual-report-inquiry:/home/admin/annual-report-inquiry \
  -v /data/models:/data/models \
  -v /etc/localtime:/etc/localtime:ro \
  -w /home/admin/annual-report-inquiry/backend \
  --env-file /home/admin/annual-report-inquiry/backend/.env \
  -e PYTHONUNBUFFERED=1 -e TZ=Asia/Shanghai \
  llama-factory:2026_02_08 \
  -c "pip install --quiet -r /home/admin/annual-report-inquiry/backend/requirements.txt && exec python3 -m uvicorn app.main:app --host 127.0.0.1 --port 30008"

docker start annual-report-inquiry
```

> **注意**：`llama-factory:2026_02_08` 镜像的 ENTRYPOINT 是 `["bash"]`，所以 CMD 不要写 `bash -c`，直接写 `-c "..."` 即可。

关键参数：
- `--network host` — 使用宿主机网络，uvicorn 绑定 127.0.0.1:30008
- `--gpus all` — 保留 GPU 访问（BERTScore 实际使用 CPU，GPU 被 vLLM 占用）
- `--restart unless-stopped` — 容器异常退出后 Docker 自动重启，CMD 重新执行（pip install + uvicorn）
- `--env-file .env` — 加载 `BERT_MODEL_PATH` 等环境变量
- `-v /data/models:/data/models` — 挂载模型目录（bert-base-chinese 等）
- `-e TZ=Asia/Shanghai` + `-v /etc/localtime` — 容器时区与宿主机一致
- 基于 `llama-factory:2026_02_08` 镜像，自带 torch/transformers/bert_score
- CMD 中 `pip install -r requirements.txt` 每次容器启动自动安装依赖（首次约 15s，后续命中缓存极快）

#### 5.2.2 日常部署流程（deploy.sh 自动执行）

deploy.sh 通过 `docker exec` 进容器操作，不涉及任何容器生命周期管理：

```bash
# 1. 检查容器是否运行（未运行则报错退出）
docker ps --format '{{.Names}}' | grep -q "^annual-report-inquiry$"

# 2. 安装/更新 Python 依赖
docker exec annual-report-inquiry pip install --quiet -r /home/admin/annual-report-inquiry/backend/requirements.txt

# 3. 重启 uvicorn
# pkill 杀掉 uvicorn（当前容器中 uvicorn 是 PID 1）→ 容器退出
# → Docker --restart unless-stopped 自动重启容器 → CMD 重新执行（pip install + uvicorn）
docker exec annual-report-inquiry pkill -f 'uvicorn app.main:app'
```

> **工作原理**：当前容器 CMD 使用 `exec uvicorn`，uvicorn 成为 PID 1。pkill 杀掉 PID 1 → 容器退出 → Docker 的 `--restart unless-stopped` 策略自动重启容器 → CMD 重新执行，加载新代码和新依赖。整个过程约 5-10 秒。

#### 5.2.3 容器维护（手动操作，非 deploy.sh 职责）

| 场景 | 操作 | 说明 |
|------|------|------|
| **日常代码更新** | deploy.sh 自动处理 | `docker exec pkill` → 容器自动重启加载新代码 |
| **新增 Python 依赖** | deploy.sh 自动处理 | `docker exec pip install` 安装后 pkill 重启 |
| **修改 .env** | 手动：`docker rm -f` → 重新 `docker create` + `start` | `--env-file` 仅在 create 时读取 |
| **更换基础镜像** | 手动：`docker rm -f` → 重新 `docker create` + `start` | 需要重建容器 |
| **查看容器内状态** | `docker exec -it annual-report-inquiry bash` | 进入容器调试 |

### 5.3 vLLM 推理服务

运行在 Docker 容器 `Qwen3-32B-lora` 中（独立于后端容器）

```bash
python3 -m vllm.entrypoints.openai.api_server \
    --host 0.0.0.0 --port 30001 \
    --max-model-len 32768 --max-num-seqs 256 \
    --gpu-memory-utilization 0.80 --dtype half \
    --tensor-parallel-size 8 --trust-remote-code \
    --served-model-name Qwen3-32B --model /data/models/Qwen3-32B \
    --enable-lora --max-loras 4 --max-cpu-loras 4 --max-lora-rank 8 \
    --lora-modules \
        risk-cot=/data/models/Qwen3-32B-lora/risk-cot \
        cot-inquiry=/data/models/Qwen3-32B-lora/cot-inquiry \
        cot-risk=/data/models/Qwen3-32B-lora/cot-risk \
        metrics-cot=/data/models/Qwen3-32B-lora/metrics-cot \
    --disable-custom-all-reduce
```

| 参数 | 值 | 说明 |
|------|------|------|
| `--tensor-parallel-size` | 8 | 8 张 V100S 并行推理 |
| `--gpu-memory-utilization` | 0.80 | 使用 80% 显存 |
| `--max-model-len` | 32768 | 最大 32K tokens 上下文 |
| `--enable-lora` | - | 启用 LoRA 适配器动态加载 |

LoRA 适配器：

| 名称 | 用途 |
|------|------|
| risk-cot | 风险信号 CoT 推理 |
| cot-inquiry | 问询事项 CoT 推理 |
| cot-risk | 风险判断 CoT 推理 |
| metrics-cot | 指标分析 CoT 推理 |

## 7. 注意事项

1. **数据库与代码分离**：数据库在 `data/bse.db`，与 `backend/`、`frontend/` 同级，部署时永不触碰
2. **后端仅替换 app/**：`mv backend/app → backend/app_<时间戳>`，logs/uploads/.env 始终保留
3. **容器 = 运行环境**：容器等同于一台配好的服务器。deploy.sh 不管理容器生命周期，只通过 `docker exec` 进容器操作服务（安装依赖、重启进程）
4. **BERT 模型本地化**：环境变量 `BERT_MODEL_PATH`（默认 `/data/models/bert-base-chinese`）。代码检测本地目录是否存在 `config.json`：存在则用本地路径（`num_layers=8, rescale_with_baseline=False`）；不存在则回退到 HF 模型名（`rescale_with_baseline=True`）。始终使用 `device='cpu'`（GPU 被 vLLM 占用），并设置 `HF_HUB_OFFLINE=1` 防止联网下载
5. **容器 .env 更新**：修改 `.env` 后需重建容器：`docker rm -f annual-report-inquiry` → 重新执行 5.2.1 的 create + start（Docker `--env-file` 仅在 create 时读取）
6. **ENTRYPOINT 注意**：`llama-factory:2026_02_08` 镜像 ENTRYPOINT 是 `["bash"]`，CMD 写 `-c "..."` 而不是 `bash -c "..."`，否则会变成 `bash bash -c` 导致报错
7. **重启机制**：`docker exec pkill uvicorn` → uvicorn(PID 1)退出 → 容器退出 → `--restart unless-stopped` 自动重启容器 → CMD 重新执行（pip install + uvicorn），整个过程约 5-10 秒
8. **依赖管理**：deploy.sh 部署时先 `docker exec pip install` 安装/更新依赖，再 `pkill uvicorn` 触发容器重启。CMD 中也包含 pip install，双重保障
9. **vLLM 独立容器**：运行在 `Qwen3-32B-lora` 容器中，与后端容器互不影响
10. **后端仅内部访问**：uvicorn 绑定 `127.0.0.1:30008`，外部通过 Nginx:30006 反代访问
11. **前端仅部署 dist/**：`build.sh` 打包时排除 `node_modules` 和 `frontend/src`，服务器上仅有编译后的静态文件
12. **回滚**：后端从 `backend/app_<时间戳>` 回退，前端从 `frontend_<时间戳>` 回退，回退后 `docker exec pkill` 重启服务
