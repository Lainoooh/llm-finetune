## 1. 页面目标

系统需要一个专门的脚本管理页面，让远程交互脚本可控、可查、可测试、可回滚。

这个页面面向管理员或开发者，不面向普通训练用户。它解决：

- 当前有哪些远程脚本。
- 哪些业务动作绑定了哪些脚本。
- 脚本参数是什么。
- 脚本版本何时修改、谁修改。
- 脚本能否在目标服务器上执行成功。
- 某次服务器探测或训练启动实际执行了哪段脚本。

## 4. 脚本列表

字段：

| 字段 | 说明 |
|---|---|
| 脚本名称 | `服务器环境探测` |
| key | `server.probe_env` |
| 分类 | `server` |
| 当前版本 | `v3` |
| 状态 | `active` / `draft` / `disabled` |
| 风险等级 | low / medium / high |
| 最近测试 | 成功/失败/未测试 |

- 风险等级
- 关键字

## 5. 脚本详情

### 5.1 基础信息

字段：

- 名称
- key
- 分类
- 描述
- 默认超时
- 输出类型
- 解析器类型
- 风险等级
- 是否启用

### 5.2 参数 Schema 编辑

展示为表格：

| 参数名 | 类型 | 必填 | 默认值 | 说明 | 约束 |
|---|---|---|---|---|---|
| work_dir | path | 是 |  | 工作目录 | 必须在允许目录下 |
| gpu_ids | gpu_ids | 否 |  | GPU IDs | 格式 `0,1` |

后端保存为 JSON Schema 风格：

```json
{
  "type": "object",
  "required": ["work_dir"],
  "properties": {
    "work_dir": {
      "type": "path",
      "description": "工作目录"
    },
    "gpu_ids": {
      "type": "gpu_ids",
      "description": "GPU IDs"
    }
  }
}
```

### 5.3 模板编辑器

第一阶段可以用 `<textarea>`，后续再接 Monaco Editor。

要求：

- 等宽字体。
- 显示行号可后续实现。
- 支持保存草稿。
- 支持格式化/复制。
- 明确显示“当前编辑版本”和“线上 active 版本”。

### 5.4 输出解析器

解析器类型：

| 类型 | 说明 |
|---|---|
| `json` | stdout 必须是 JSON |
| `regex` | 使用正则提取字段 |
| `builtin` | 使用后端内置解析器，如 GPU CSV |
| `none` | 原样返回 |

对于 `regex`，页面需要配置：

```json
{
  "patterns": {
    "loss": "loss=([0-9.]+)",
    "step": "step=(\\d+)"
  }
}
```

## 6. 业务动作绑定

脚本不是孤立存在的，需要绑定到业务动作。

表：`script_bindings`

| 字段 | 说明 |
|---|---|
| action_key | 业务动作，如 `server.probe` |
| script_key | 脚本 key |
| script_version | 使用版本，null 表示最新 active |
| enabled | 是否启用 |

页面展示：

```text
业务动作             绑定脚本
服务器环境探测        server.probe_env v3
工作目录检查          server.check_workdir v1
启动训练              subtask.start_train v2
停止训练              subtask.stop_train v1
读取日志              subtask.read_log_since v1
```

这样后续替换脚本不需要改业务代码。

## 7. 测试面板

测试面板包含：

- 选择服务器对象。
- 自动生成参数表单。
- Dry Run 按钮：只渲染脚本，不执行。
- Execute Test 按钮：在选中服务器执行。
- 输出区：stdout、stderr、exit_code。
- Parser 结果区：展示结构化解析结果。

交互流程：

```text
选择 server_profile
  -> 根据 param_schema 填参数
  -> 点击 Dry Run
  -> 查看渲染后的脚本
  -> 点击 Execute Test
  -> 后端创建 script_test_run
  -> 远程执行
  -> 显示输出和解析结果
```

## 8. 版本管理

版本规则：

- 修改 active 脚本时，默认生成 draft 版本。
- draft 测试通过后才允许发布为 active。
- 每次发布 version +1。
- 可回滚到历史版本。
- disabled 脚本不能被业务动作调用。

页面操作：

- 保存草稿
- 测试草稿
- 发布
- 禁用
- 回滚
- 查看 diff

## 9. 执行审计

脚本详情页展示最近执行记录：

| 时间 | 业务动作 | 目标 | 执行状态 | 退出码 | 耗时 | 操作 |
|---|---|---|---|---|---|---|
| 2026-05-21 15:30 | server.probe | A100-GPU0 | succeeded | 0 | 1.2s | 查看 |

点击查看：

- 渲染后的脚本。
- 参数。
- stdout/stderr。
- parser 结果。
- 关联的 ExecutionRun。

## 12. 权限策略

第一阶段可不做复杂用户系统，但至少区分：

| 操作 | 默认限制 |
|---|---|
| 查看脚本 | 允许 |
| 测试 low/medium 脚本 | 允许开发环境 |
| 发布脚本 | 管理员 |
| high 风险脚本执行 | 需要确认 |
| 查看 token | 永不允许前端查看 |
