# 并发控制与日志设计 [已实现]

<!-- Created: 2026-04-27 -->

## 1. 概述

系统通过 2 层 Semaphore 控制 LLM 调用并发，通过 httpx 连接池管理 HTTP 连接，通过结构化日志实现链路追踪。

---

## 2. 并发控制

### 2.1 2 层 Semaphore 架构

```
请求入口
    ↓
任务级 Semaphore (LLM_TASK_CONCURRENCY=1)
    │  限制同时执行 LLM 密集步骤的任务数
    ↓
请求级 Semaphore (LLM_MAX_CONCURRENT_REQUESTS=5)
    │  限制全局 LLM API 并发调用数
    ↓
httpx 连接池 (max_connections=20)
    ↓
LLM API
```

### 2.2 任务级 Semaphore

```python
# routers/workflow.py
LLM_STEP_INDICES = {2, 4, 6}
_llm_step_semaphore = asyncio.Semaphore(
    int(os.environ.get("LLM_TASK_CONCURRENCY", "1"))
)
```

- 仅 LLM 密集步骤（Step 2, 4, 6）受保护
- 默认同时 1 个任务的 LLM 步骤运行
- Step 0, 1, 3, 5 不受此限制（无 LLM 调用）

### 2.3 请求级 Semaphore

```python
# services/llm_service.py
_llm_request_semaphore = asyncio.Semaphore(
    int(os.environ.get("LLM_MAX_CONCURRENT_REQUESTS", "5"))
)
```

- 全局限制，防止同时发送过多 LLM API 请求
- `chat_batch_raw()` 中每个并发调用都需获取此 Semaphore

## 3. httpx 连接池

### 3.1 配置

```python
# services/llm_service.py
httpx.AsyncClient(
    timeout=httpx.Timeout(180.0, connect=10.0),
    limits=httpx.Limits(
        max_connections=20,
        max_keepalive_connections=10
    ),
    trust_env=False,
)
```

| 参数 | 值 | 说明 |
|------|-----|------|
| timeout (请求) | 180s | LLM 响应可能较慢 |
| timeout (连接) | 10s | 连接建立超时 |
| max_connections | 20 | 最大并发连接数 |
| max_keepalive | 10 | Keep-Alive 连接数 |
| trust_env | False | 忽略代理环境变量 |

### 3.2 生命周期

- 全局单例，lazy 初始化
- FastAPI shutdown 事件中优雅关闭：`await _http_client.aclose()`

## 4. 结构化日志

### 4.1 双格式输出

#### Console Handler（人类可读）

```
2026-04-27 15:14:00 | INFO  | app.services.llm_service | [task:abc123] LLM API 调用完成 (1234ms)
```

#### File Handler（JSON 格式）

```json
{
  "timestamp": "2026-04-27T15:14:00.000Z",
  "level": "INFO",
  "logger": "app.services.llm_service",
  "task_id": "abc123",
  "conversation_id": "conv-xyz",
  "message": "LLM API 调用完成 (1234ms)"
}
```

### 4.2 上下文变量（ContextVar）

```python
# logging_config.py
from contextvars import ContextVar

ctx_task_id = ContextVar('task_id', default='-')
ctx_conversation_id = ContextVar('conversation_id', default='-')
```

- 在工作流引擎中设置：`ctx_task_id.set(task_id)`
- 自动传播到异步子任务
- 日志 Filter 自动注入到每条日志记录

### 4.3 日志文件配置

| 参数 | 值 |
|------|-----|
| 文件位置 | `logs/app.log` |
| 最大大小 | 10MB |
| 备份数量 | 5 |
| 编码 | UTF-8 |
| Handler | RotatingFileHandler |

### 4.4 第三方日志降噪

```python
logging.getLogger("httpx").setLevel(logging.WARNING)
logging.getLogger("httpcore").setLevel(logging.WARNING)
```

## 6. 错误处理

### 6.1 LLM 调用异常

```python
try:
    response = await _http_client.post(...)
except httpx.TimeoutException:
    logger.error(f"LLM API 超时: {model_name}")
    raise
except httpx.HTTPStatusError as e:
    logger.error(f"LLM API 错误: {e.response.status_code}")
    raise
```

### 6.2 性能日志

每次 LLM 调用记录：
- 请求耗时（ms）
- 模型名称
- Token 消耗（如 API 返回）
- 成功/失败状态
