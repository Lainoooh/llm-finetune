## 1. 工作流概述

### 1.1 工作流程
北交所年报审查系统采用 7 阶段工作流，结合自动化 LLM 处理和人工审核，确保年报审查的准确性和合规性。

### 1.2 工作流特点
- **混合模式**: 5 个自动步骤 + 2 个人工审核节点
- **异步执行**: 后端 BackgroundTask + 前端 2s 轮询
- **可中断**: 人工审核节点暂停等待决策
- **可追溯**: 每个步骤记录输入/输出/日志/耗时
- **并发控制**: LLM 密集步骤受 Semaphore 保护

## 2. 工作流步骤定义

### 2.1 步骤总览

| 索引 | 步骤名称 | 类型 | 说明 | LLM |
|------|---------|------|------|-----|
| 0 | 年报上传和审查 | auto | 解析 PDF / 接收 JSON 输入 | 否 |
| 1 | 指标提取 | auto | 清洗指标值，存入 DB | 否 |
| 2 | RDU风险信号分析 | auto | 2 阶段 LLM + BERTScore 匹配 | **是** |
| 3 | RDU风险信号触发判断 | manual_risk | 人工确认触发的风险信号 | 否 |
| 4 | 问询事项生成 | auto | 2 阶段 LLM 生成问询逻辑+事项 | **是** |
| 5 | 问询事项确认 | manual_item | 人工确认问询内容 | 否 |
| 6 | 起草正式问询函 | auto | 汇总生成最终问询函 | **是** |

## 3. 状态机

### 3.1 任务状态

```
pending → running → paused → running → completed
                      ↓                    ↓
                    failed              failed
```

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| pending | 待执行 | 任务创建时 |
| running | 执行中 | 工作流启动 / 人工确认后继续 |
| paused | 暂停 | 到达 manual_risk 或 manual_item 步骤 |
| completed | 完成 | 所有步骤执行完毕 |
| failed | 失败 | 执行出错 |

### 3.2 步骤状态

```
pending → running → completed
               ↓
             failed
```

### 3.3 完整状态转换

```
┌─────────┐
│ pending  │ ← 任务创建
└────┬─────┘
     │ startWorkflow()
     ▼
┌─────────┐
│ running  │ ← Step 0 (auto) → Step 1 (auto)
└────┬─────┘
     │ Step 2 (auto, LLM)
     ▼
┌─────────┐
│ paused   │ ← Step 3 (manual_risk) 等待用户确认风险信号
└────┬─────┘
     │ resumeWorkflow()
     ▼
┌─────────┐
│ running  │ ← Step 4 (auto, LLM)
└────┬─────┘
     │
     ▼
┌─────────┐
│ paused   │ ← Step 5 (manual_item) 等待用户确认问询事项
└────┬─────┘
     │ resumeWorkflow()
     ▼
┌─────────┐
│ running  │ ← Step 6 (auto, LLM)
└────┬─────┘
     │
     ▼
┌───────────┐
│ completed  │ ← 生成问询函
└───────────┘
```

## 4. 步骤详细设计

### 4.1 Step 0: 年报上传和审查 (auto)
- 接收 `metrics_json` JSON 输入（当前模式），或解析 PDF 文件（预留）
- 创建会话关联
- 返回：确认消息

### 4.2 Step 1: 指标提取 (auto)
- 从 `metrics_json` 解析指标数据
- 指标值清洗：去除单位后缀（元、%、万、亿）、去除千分位逗号、零值转空
- 存入 `indicator_values` 表
- 返回：提取的指标数量

### 4.3 Step 2: RDU 风险信号分析 (auto, LLM)

**2 阶段 LLM 调用 + BERTScore 匹配**：

```
Phase 1: metrics-cot (purpose=risk_judgment)
  输入：每个风险信号关联的指标 → "指标名:指标值" 拼接
  输出：风险判断逻辑（raw + parsed）
       ↓
Phase 2: cot-risk (purpose=risk_signal)
  输入：Phase 1 完整输出（保留【】标记）
  输出：风险信号名称预测
       ↓
BERTScore 匹配：
  预测值 vs 标准风险信号名称
  similarity > 0.9 → is_triggered = True
  similarity ≤ 0.9 → is_triggered = False
```

- 并发调用：`chat_batch_raw()` 批量并发 LLM 调用
- 结果存入：`risk_signals` 表（含 logic, risk, similarity_score）
- 此步为 **auto** 类型，完成后自动进入 Step 3

### 4.4 Step 3: RDU 风险信号触发判断 (manual_risk)
- 从 DB 读取 `risk_signals`（Step 2 的结果）
- 返回信号列表供确认面板展示
- 任务状态设为 `paused`，等待用户：
  - 查看每个风险信号的判断逻辑和相似度
  - 勾选/取消触发状态
  - 点击"授权执行下一步"

### 4.5 Step 4: 问询事项生成 (auto, LLM)

**2 阶段 LLM 调用**：

```
Phase 1: risk-cot (purpose=inquiry_logic)
  输入：已触发信号的 logic 字段（Step 2 输出）
  输出：问询逻辑 → 存入 risk_signals.inquiry_logic

Phase 2: cot-inquiry (purpose=inquiry_item)
  输入：Phase 1 原始输出（保留【】标记）
  输出：问询事项 → 存入 risk_signals.inquiry_item
```

- 仅处理 `is_triggered=True` 的信号（经 Step 3 专家确认）
- 并发调用：每个信号独立的 LLM 调用

### 4.6 Step 5: 问询事项确认 (manual_item)
- 展示每个信号的问询逻辑 + 问询事项
- 用户可修改内容
- 确认后继续

### 4.7 Step 6: 起草正式问询函 (auto, LLM)
- 汇总所有确认的问询事项
- LLM 生成最终格式化问询函
- 存入 `inquiry_letters` 表
- 任务状态设为 `completed`

## 5. 并发控制

### 5.1 任务级 Semaphore
```python
_llm_step_semaphore = asyncio.Semaphore(
    int(os.environ.get("LLM_TASK_CONCURRENCY", "1"))
)
```
- 仅 LLM 密集步骤 {2, 4, 6} 受此 Semaphore 保护
- 默认同时 1 个任务的 LLM 步骤运行

### 5.2 请求级 Semaphore
- LLM 服务层另有请求级 Semaphore（默认 5 并发）

## 6. 前端交互

### 6.1 轮询机制
- 2s 间隔轮询 `GET /api/tasks/{id}/workflow`
- running/paused → 继续轮询
- completed/failed → 停止轮询

### 6.2 前端状态机颜色

| 任务状态 | 颜色 | 消息卡片图标 | 步骤圆点 |
|---------|------|-------------|---------|
| running | 蓝色 | Loader2 旋转 | 蓝色脉动 |
| paused | 橙色 | PauseCircle | 橙色 PauseCircle |
| completed | 绿色 | CheckCircle2 | 绿色 Check |
| failed | 红色 | XCircle | 红色 X |

详见 [06-前端交互设计.md](./06-前端交互设计.md)

## 7. 错误处理

- 失败时记录 `workflow_steps.error_message`
- 任务状态设为 `failed`
- 前端在工作流面板和消息卡片中展示失败状态
- 当前版本不支持自动重试
