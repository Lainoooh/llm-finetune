# 开发任务拆分与自测试指南

> 状态：[草案]  
> 创建时间：2026-05-21  
> 最后更新：2026-05-21

本文档面向小型智能体或分工开发者，描述如何把当前设计落地为可运行版本，并给出每个任务的文件边界、验收标准和自测试方法。

## 1. 总体开发原则

1. 先实现后端 API 和 Jupyter 执行器，再替换前端 mock。
2. 所有远程命令必须来自脚本库，不允许业务代码硬编码大段 shell。
3. 训练进程必须后台运行，不能长期占用 Jupyter WebSocket 队列。
4. 远程 token 只能在后端环境变量或加密配置中出现。
5. 每个功能都要有本地 mock 测试和真实 Jupyter smoke test。

## 2. 任务 A：创建 Python FastAPI 后端骨架

### 2.1 目标

建立 `backend/`，能启动服务并返回健康检查。

### 2.2 建议文件

```text

  app/
    main.py
    core/config.py
    core/errors.py

```

cd backend

curl http://127.0.0.1:8787/api/health

```json

```

```bash

```

- `/api/health`
- 配置读取

## 5. 任务 D：JupyterTerminalExecutor

### 5.1 目标

把 Jupyter REST + WebSocket 封装为 Python 执行器。

### 5.2 文件

```text
backend/app/executors/base.py
backend/app/executors/jupyter_terminal/executor.py
backend/app/executors/jupyter_terminal/session_manager.py
backend/app/executors/jupyter_terminal/command_queue.py
backend/app/executors/jupyter_terminal/protocol.py
```

### 5.3 关键行为

- `POST /api/terminals` 创建 terminal。
- WebSocket 连接 terminal。
- 发送 base64 包装脚本。
- 使用唯一 marker 判断完成。
- 超时失败。
- WebSocket 断开时 session generation +1。
- 旧队列失败，不自动迁移。

### 5.4 验收

开发调试接口：

```text
POST /api/debug/remote-run
```

请求：

```json
{"cmd":"df -h | head","timeoutMs":10000}
```

响应包含：

- exit_code
- stdout
- session_generation

注意：该接口只能在 `ENABLE_DEBUG_REMOTE_RUN=true` 时启用。

## 7. 任务 F：资源锁服务

### 7.1 目标

防止多个子任务占用同一 GPU。

### 7.2 文件

```text
backend/app/services/resource_lock_service.py
backend/app/models/resource_lock.py
```

### 7.3 必测场景

1. GPU 无锁，申请成功。
2. GPU 完全相同，第二次申请失败。
3. GPU 部分重叠，第二次申请失败。
4. GPU 不重叠，申请成功。
5. run 结束后释放锁。

## 9. 任务 H：配置同步和训练启动

### 9.1 目标

打通一次真实训练启动闭环。

### 9.2 API

```text
POST /api/subtasks/:id/sync
POST /api/subtasks/:id/start
POST /api/subtasks/:id/stop
GET /api/runs/:id
```

### 9.3 远程动作

1. 创建子任务目录。
2. 写入 `train.yaml`。
3. 写入 `dataset_info.json`。
4. 写入 `run.sh`。
5. 后台启动 `run.sh`。
6. 写入 `run.pid`。
7. 更新 run/subtask 状态。

### 9.4 自测试

先不要跑真实长训练，创建一个测试脚本：

```bash
for i in 1 2 3; do echo "step=$i loss=0.$i"; sleep 1; done
```

验收：

- run 状态从 queued -> running -> succeeded。
- 日志可读取。
- GPU 锁被申请并释放。

## 12. 端到端 smoke test

### 12.1 服务器探测

```bash
curl -X POST http://127.0.0.1:8787/api/servers/srv-a/probe
```

期望：

- status=online
- gpu 非空
- cuda 或 torch 至少一个可解析
- disk 非空

### 12.2 子任务假训练

```bash
curl -X POST http://127.0.0.1:8787/api/subtasks/task_002/start \
  -H 'content-type: application/json' \
  --data '{"dryRunTraining":true}'
```

期望：

- 返回 runId。
- 日志流能看到 step/loss。
- 最终状态 succeeded。

### 12.3 会话断开恢复

人为让 Jupyter terminal 退出：

```bash
POST /api/debug/remote-run {"cmd":"exit","mode":"raw"}
```

期望：

- 当前 remote command 返回 `REMOTE_SESSION_RESET`。
- session generation 增加。
- 新的服务器探测请求可成功。
- 旧队列不自动迁移。

## 13. 开发顺序建议

推荐顺序：

1. 任务 A：FastAPI 后端骨架。
2. 任务 B：数据库模型。
3. 任务 C：脚本库服务。
4. 任务 D：JupyterTerminalExecutor。
5. 任务 E：服务器探测 API + 前端替换 mock。
6. 任务 F：资源锁。
7. 任务 G：子任务持久化。
8. 任务 H：训练启动。
9. 任务 I：实时日志。
10. 任务 J：脚本管理页面。

这样每一步都有可验证结果，不会一口气改太多。
