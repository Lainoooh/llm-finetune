## 1. 模块目标

在子任务配置页的「数据集」Tab 中，提供完整的数据集生命周期管理能力：

1. **文件上传**：将本地数据文件上传到子任务的远程工作目录
2. **dataset_info 自动配置**：上传后自动读取远端 `dataset_info.json`，基于上传文件进行合并/新增，并展示同步状态
3. **数据集列表与预览**：下拉选择已有 dataset，弹窗预览数据内容
4. **双模式上传入口**：本地上传 + 训练样本库（预留）

## 2. 文件上传通道设计

### 2.1 现状分析

当前远程执行框架（`RemoteTransport`）基于终端 stdin/stdout 通道，设计用于执行命令，不具备文件传输能力。

**问题**：
- 终端有输出缓冲区限制，大文件容易丢数据
- base64 编码膨胀 33%，15MB 文件变 20MB
- 没有进度回调机制

### 2.2 双通道方案

根据服务器的 `accessType` 自动选择上传通道：

| 接入类型 | 上传通道 | 实现方式 | 适用场景 |
|----------|----------|----------|----------|
| **SSH** | SFTP | `asyncssh.start_sftp_client()` 原生文件传输 | 稳定可靠，有进度回调，支持大文件 |
| **Jupyter** | Contents API | Jupyter REST API `/api/contents` | 文件上传接口，受 Jupyter 配置限制（默认 ~100MB） |
| **兜底** | Base64 分块 | 现有终端通道 `echo base64 \| base64 -d >> file` | 小文件（< 1MB）或前两种失败时降级 |

### 2.3 SSH + SFTP 实现

```python
class SshFileTransport:
    """基于 asyncssh SFTP 的文件传输"""

    def __init__(self, endpoint: SshEndpoint):
        self.endpoint = endpoint
        self.connection = None
        self.sftp = None

    async def connect(self):
        import asyncssh
        kwargs = {
            "host": self.endpoint.host,
            "port": self.endpoint.port,
            "username": self.endpoint.username,
            "known_hosts": None,
        }
        if self.endpoint.private_key:
            kwargs["client_keys"] = [asyncssh.import_private_key(self.endpoint.private_key)]
        elif self.endpoint.password:
            kwargs["password"] = self.endpoint.password
        self.connection = await asyncssh.connect(**kwargs)
        self.sftp = await self.connection.start_sftp_client()

    async def upload(
        self,
        local_path: str,
        remote_path: str,
        progress_callback: Callable[[int, int], None] | None = None,
    ) -> UploadResult:
        """上传文件，支持进度回调"""
        file_size = os.path.getsize(local_path)
        uploaded = 0
        chunk_size = 64 * 1024  # 64KB 分块

        async with self.sftp.open(remote_path, "wb") as remote_file:
            with open(local_path, "rb") as local_file:
                while True:
                    chunk = local_file.read(chunk_size)
                    if not chunk:
                        break
                    await remote_file.write(chunk)
                    uploaded += len(chunk)
                    if progress_callback:
                        progress_callback(uploaded, file_size)

        # 校验 md5
        remote_md5 = await self._remote_md5(remote_path)
        local_md5 = self._local_md5(local_path)
        if remote_md5 != local_md5:
            raise UploadError(f"MD5 mismatch: local={local_md5}, remote={remote_md5}")

        return UploadResult(remote_path=remote_path, size=file_size, md5=remote_md5)

    async def _remote_md5(self, path: str) -> str:
```

### 2.4 Jupyter Contents API 实现

```python
class JupyterFileTransport:
    """基于 Jupyter Contents API 的文件上传"""

    def __init__(self, endpoint: JupyterEndpoint):
        self.endpoint = endpoint

    async def upload(
        self,
        local_path: str,
        remote_path: str,
        progress_callback: Callable[[int, int], None] | None = None,
    ) -> UploadResult:
        """通过 Jupyter Contents API 上传文件"""
        import httpx
        import base64

        file_size = os.path.getsize(local_path)
        with open(local_path, "rb") as f:
            content = base64.b64encode(f.read()).decode("ascii")

        # Jupyter Contents API
        url = f"{self.endpoint.base_url}/api/contents/{remote_path}"
        headers = {"Authorization": f"token {self.endpoint.token}"}
        payload = {
            "type": "file",
            "format": "base64",
            "content": content,
        }

        async with httpx.AsyncClient(timeout=60) as client:
            response = await client.put(url, json=payload, headers=headers)
            response.raise_for_status()

        if progress_callback:
            progress_callback(file_size, file_size)

        return UploadResult(
            remote_path=remote_path,
            size=file_size,
            md5=None,  # Jupyter API 不返回 md5，需额外校验
        )
```

### 2.5 通道选择策略

```python
class FileUploadService:
    """文件上传服务，自动选择通道"""

    async def upload_to_server(
        self,
        server: ServerProfile,
        local_path: str,
        remote_path: str,
        progress_callback: Callable | None = None,
    ) -> UploadResult:
        if server.access_type == "ssh":
            transport = SshFileTransport(SshEndpoint(
                host=server.host,
                port=server.ssh_port,
                username=server.user,
                password=server.password,
                private_key=server.ssh_key,
            ))
        elif server.access_type == "jupyter":
            transport = JupyterFileTransport(JupyterEndpoint(
                base_url=server.jupyter_base_url,
                token=server.token,
            ))
        else:
            raise ValueError(f"Unsupported access type: {server.access_type}")

        try:
            await transport.connect()
            return await transport.upload(local_path, remote_path, progress_callback)
        finally:
            await transport.close()
```

```python
# 后端 WebSocket endpoint
@router.websocket("/ws/upload/{subtask_code}")
async def upload_progress_ws(websocket: WebSocket, subtask_code: str):
    await websocket.accept()
    upload_manager.subscribe(subtask_code, websocket)
    try:
        while True:
            await websocket.receive_text()  # 保持连接
    except WebSocketDisconnect:
        upload_manager.unsubscribe(subtask_code, websocket)

# 上传时触发进度事件
async def on_progress(subtask_code: str, filename: str, uploaded: int, total: int):
    await upload_manager.broadcast(subtask_code, {
        "type": "progress",
        "filename": filename,
        "uploaded": uploaded,
        "total": total,
        "percent": round(uploaded / total * 100, 1),
    })
```

## 4. 功能模块设计

### 4.1 文件上传

#### 4.1.1 上传目标

文件上传到子任务关联的远程服务器工作目录：

```
{server.workDir}/{task.taskCode}/{subtask.subtaskCode}/
```

例如：`/home/admin/workdir/T20260522001/ST20260522001A/train_data.jsonl`

#### 4.1.2 支持的文件格式

| 格式 | 扩展名 | 说明 |
|------|--------|------|
| JSONL | `.jsonl` | 每行一个 JSON 对象，LLaMA-Factory 推荐格式 |
| JSON | `.json` | 单个 JSON 数组 |
| CSV | `.csv` | 需指定列映射 |
| Parquet | `.parquet` | 列式存储，大数据集 |

#### 4.1.3 双模式入口

```
┌─────────────────────────────────────────┐
│  [本地文件上传]    [训练样本库 🔒]        │
│                                         │
│  本地上传：直接从浏览器选择文件           │
│  训练样本库：从统一样本库选择（待开发）    │
└─────────────────────────────────────────┘
```

**训练样本库（预留）**：
- 按钮置灰 + 锁定图标
- Tooltip 提示"训练样本库开发中"
- API 预留 `POST /api/subtasks/{code}/upload-from-library`

**训练样本库概念**：统一的数据文件管理中心，所有子任务共享。用户在样本库中构建 `训练.json` + `评测.json`，子任务直接选文件拷贝到远端。

### 4.2 dataset_info.json 自动配置

#### 4.2.1 LLaMA-Factory dataset_info.json 格式

```json
{
  "train_data": {
    "file_name": "train_data.jsonl",
    "formatting": "alpaca",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    }
  },
  "eval_data": {
    "file_name": "eval_data.jsonl",
    "formatting": "sharegpt",
    "tags": {
      "role_tag": "role",
      "content_tag": "content",
      "user_tag": "user",
      "assistant_tag": "assistant"
    }
  }
}
```

#### 4.2.2 同步流程

```
上传完成
  ↓
后端: 读取远程 dataset_info.json（不存在则初始化 {}）
  ↓
后端: 根据上传文件名自动生成 dataset 配置项
  ↓
后端: 合并逻辑：
  - 如果 dataset_name 已存在 → 更新 file_name / columns
  - 如果 dataset_name 不存在 → 新增条目
  ↓
后端: 写回远程 dataset_info.json
  ↓
后端: 更新本地 DB 中 subtask.dataset_info 字段
  ↓
前端: 轮询 / WebSocket 接收同步状态
```

#### 4.2.3 同步状态展示

每个 dataset 条目有四种状态：

| 状态 | 图标 | 说明 |
|------|------|------|
| 已同步 | ✅ | 远端 dataset_info.json 包含此条目且版本一致 |
| 同步中 | 🔄 | 正在写入远端 |
| 未同步 | ⚠️ | 远端有变更，或本次上传后尚未触发同步 |
| 同步失败 | ❌ | 网络/权限异常 |

#### 4.2.4 前端配置表单

用户可手动调整列映射和格式：

```

│  文件名:       [train_data.jsonl] (自动填充，可修改)       │
```

#### 4.2.5 智能列映射推断

上传文件后，后端读取文件前 5 行，自动推断列映射：

| 文件列名 | 推断映射 |
|----------|----------|
| `instruction` | prompt |
| `input` | query |
| `output` | response |
| `messages` / `conversations` | sharegpt 格式 |
| `prompt` + `completion` | prompt + response |
| `question` + `answer` | prompt + response |

推断结果展示在前端配置表单中，用户可手动调整。

#### 4.3.3 数据预览读取策略：分页读取

**不使用流式传输**，采用分页读取。

**理由**：
- 场景是"看几条数据长什么样"，不是全量下载
- 训练文件是 JSONL（每行一条），天然支持按行定位
- 流式传输增加复杂度但没有实际收益
- 不管文件有 1000 条还是 10 万条，每次只传 10 行（约几 KB）

**实现**：

```
首次打开预览:
  1. SSH/Jupyter → wc -l < file.jsonl          → 拿到总行数（缓存到 DB，5分钟过期）
  2. SSH/Jupyter → sed -n '1,10p' file.jsonl   → 读第 1-10 行

翻页到第 500 页:
  SSH/Jupyter → sed -n '4991,5000p' file.jsonl  → 只传 10 行回来
```

**远程命令**：

```bash
# 获取总行数（JSONL）
wc -l < {workdir}/{filename}

# 获取总行数（JSON 数组，计算元素个数）
python3 -c "import json; print(len(json.load(open('{workdir}/{filename}'))))"

# 分页读取 JSONL（第 start 行到第 end 行）
sed -n '{start},{end}p' {workdir}/{filename}

# 分页读取 JSON 数组
python3 -c "
import json
data = json.load(open('{workdir}/{filename}'))
start = {start} - 1
end = {end}
print(json.dumps(data[start:end], ensure_ascii=False))
"
```

**性能保证**：
- `sed -n` 是 seek 定位，不会从头读整个文件
- 每次只传输 10 行数据（约 2-5KB）
- 总行数只计算一次，缓存 5 分钟
- 10 万条数据和 1000 条数据的翻页速度完全一致

### 6.2 文件上传 Service

```python
class FileUploadService:
    """文件上传服务"""

    def __init__(self):
        self._progress_callbacks: dict[str, list[Callable]] = {}

    def subscribe_progress(self, subtask_code: str, callback: Callable):
        """订阅上传进度"""
        self._progress_callbacks.setdefault(subtask_code, []).append(callback)

    def unsubscribe_progress(self, subtask_code: str, callback: Callable):
        """取消订阅"""
        cbs = self._progress_callbacks.get(subtask_code, [])
        if callback in cbs:
            cbs.remove(callback)

    async def _broadcast_progress(self, subtask_code: str, event: dict):
        """广播进度事件"""
        for cb in self._progress_callbacks.get(subtask_code, []):
            await cb(event)

    async def upload(
        self,
        subtask_code: str,
        file: UploadFile,
        filename: str | None = None,
    ) -> UploadResult:
        # 1. 保存到本地临时文件
        # 2. 获取子任务关联的服务器
        # 3. 根据 access_type 选择上传通道
        # 4. 上传到远端
        # 5. 校验 md5
        # 6. 广播进度事件
        # 7. 清理临时文件
        ...
```

### 7.3 上传进度 WebSocket

```javascript
useEffect(() => {
  const ws = new WebSocket(`ws://${host}/ws/upload/${subtaskCode}`);
  ws.onmessage = (e) => {
    const event = JSON.parse(e.data);
    if (event.type === "progress") {
      setUploadProgress(prev => ({
        ...prev,
        [event.filename]: event.percent,
      }));
    } else if (event.type === "complete") {
      setUploadProgress(prev => {
        const next = { ...prev };
        delete next[event.filename];
        return next;
      });
      refreshDatasets();  // 上传完成后刷新 dataset 列表
    }
  };
  return () => ws.close();
}, [subtaskCode]);
```

## 9. 交互流程

### 9.1 完整上传 → 同步 → 选择流程

```
用户拖拽 train.jsonl 到上传区域
  ↓
前端: POST /upload (multipart)
前端: 连接 WebSocket 监听进度
  ↓
后端: 保存到本地临时文件
后端: 获取子任务关联服务器
后端: 根据 access_type 选择通道（SSH SFTP / Jupyter API）
后端: 分块上传到远端，每块触发进度回调
  ↓
前端: WebSocket 收到 progress 事件，更新进度条
  ↓
后端: 上传完成，校验 md5
后端: 读取远端 dataset_info.json
后端: 读取文件前 5 行，推断列映射
后端: 生成 dataset 配置 → 合并写入 dataset_info.json
后端: 更新 DB（dataset_info, dataset_sync_status, uploaded_files, dataset_row_cache）
后端: WebSocket 推送 complete 事件
  ↓
前端: 上传完成 → 自动刷新 dataset 列表 → 显示同步状态 ✅
前端: 训练集下拉自动选中 "train_data"
  ↓
用户点击 [预览数据] → 弹窗显示数据内容（分页读取）
```

### 9.2 编辑已有 dataset 配置

```
用户在配置表单中修改列映射
  ↓
前端: PATCH /datasets/{name}
  ↓
后端: 合并更新 dataset_info.json → 异步同步到远端
  ↓
前端: 同步状态变为 🔄 → 完成后变为 ✅
```

### 9.3 翻页预览

```
用户点击"下一页"
```

## 10. 边界情况与错误处理

| 场景 | 处理方式 |
|------|----------|
| 远端 dataset_info.json 不存在 | 自动创建 `{}`，首次写入 |
| 远端 dataset_info.json 格式错误 | 报错提示，保留原始文件备份（.bak） |
| 上传文件重名 | 默认覆盖，可配置为追加时间戳 |
| 上传中断 | 清理远端临时文件（.tmp 后缀） |
| 远程服务器离线 | 上传按钮置灰，提示"服务器离线，请先完成连通性检测" |
| 数据集文件被删除 | 同步状态变为 ⚠️，下拉标记"(文件缺失)" |
| SFTP 连接失败 | 降级到 base64 分块传输（小文件）或报错（大文件） |
| Jupyter API 超限 | 提示文件过大，建议使用 SSH 接入 |
| 行数缓存过期 | 预览时重新计算，更新缓存 |
