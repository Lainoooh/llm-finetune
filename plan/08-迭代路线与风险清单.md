# 迭代路线与风险清单

> 状态：[草案]  
> 创建时间：2026-05-21  
> 最后更新：2026-05-21

## 1. 迭代目标

系统应从当前纯前端原型，逐步演进为可真实操作 LLaMA-Factory 容器的微调平台。路线需要控制风险，先打通关键闭环，再做完整资源管理。

## 2. Phase 0：现状固化

目标：

- 明确当前页面和数据模型。
- 建立 plan 文档。
- 保持前端可运行。

交付：

- 设计文档。
- 不改动现有业务代码。

## 3. Phase 1：临时 Jupyter 插件接入服务器探测

目标：

- 新增后端 sidecar 服务。
- 接入 Jupyter Terminal 执行器。
- 实现服务器环境探测 API。
- 替换 ServersPage 中的 mock 连通性检查。

交付：

- `server/plugins/remoteExecutor/jupyterTerminalExecutor.mjs`
- `POST /api/servers/:id/probe`
- `POST /api/servers/probe-draft`
- `src/api/serversApi.js`
- 前端服务器环境信息真实刷新。

验收：

- 点击服务器行“连通性检查”，可以返回 GPU、CUDA、PyTorch、LLaMA-Factory、磁盘。
- 探测失败时显示离线和错误信息。
- Token 不出现在前端代码。

## 4. Phase 2：服务器资源与 GPU 切分

目标：

- 引入物理服务器和逻辑服务器对象。
- 支持按 GPU 创建多个 ServerProfile。
- 展示 GPU 空闲/占用。

交付：

- 服务器保存 API。
- GPU 探测和拆分 API。
- 服务器编辑页增加 GPU 卡片选择。
- 资源锁基础表。

验收：

- 一台 8 卡机器可以拆成 8 个单卡服务器对象。
- 子任务选择服务器时看到的是逻辑服务器对象。

## 5. Phase 3：任务与子任务持久化

目标：

- 任务列表和子任务列表脱离 mock。
- 新建、编辑、复制、删除真实保存。
- 子任务绑定服务器对象。

交付：

- Task API。
- Subtask API。
- 前端 `TaskListPage`、`TaskDetailPage`、`SubtaskPage` 接 API。

验收：

- 刷新页面后任务和子任务不丢失。
- 子任务配置能保存并再次打开。

## 6. Phase 4：训练启动闭环

目标：

- 生成 LLaMA-Factory YAML。
- 同步配置到远程工作目录。
- 启动训练。
- 读取日志。
- 训练结束更新状态。

交付：

- `POST /api/subtasks/:id/sync`
- `POST /api/subtasks/:id/start`
- `POST /api/subtasks/:id/stop`
- `GET /api/runs/:id/logs/stream`
- GPU 资源锁。

验收：

- 一个子任务可以在远程容器启动真实训练。
- 页面实时看到日志。
- 训练结束后子任务状态变为 succeeded 或 failed。
- 同一 GPU 不会被两个子任务同时启动。

## 7. Phase 5：评测与综合对比

目标：

- 执行业务评测。
- 解析评测结果。
- 生成 Loss 和评测对比。
- 导出报告。

交付：

- Eval API。
- Metrics parser。
- ComparePage 接真实数据。

验收：

- 多个子任务完成后，可在综合对比页看到真实曲线和指标。
- 可导出报告。

## 8. Phase 6：标准 LLaMA-Factory 镜像部署

目标：

- 沉淀标准微调镜像。
- 支持容器部署、启动、停止和健康检查。
- 从 Jupyter 临时执行转向 SSH/Docker 执行器。

交付：

- 镜像配置模型。
- Docker 部署 API。
- DockerExecExecutor 或 SshExecutor。

验收：

- 新服务器可通过页面部署标准镜像。
- 部署后自动完成环境探测。

## 9. 主要风险

### 9.1 Jupyter 通道稳定性

风险：

- WebSocket 断开。
- Terminal 会话被关闭。
- 长训练命令导致输出过大或超时。

缓解：

- 执行器使用 session generation。
- 会话断开后旧队列失败并重建。
- 长训练采用异步 run，不用同步等待 HTTP。
- 日志持久化。

### 9.2 训练进程与会话生命周期不一致

风险：

- Jupyter 会话断开但训练进程仍在后台运行。
- 后端误以为训练失败并释放 GPU 锁。

缓解：

- 启动训练时写 pid 文件。
- 定期探测 pid 是否存在。
- 只有确认进程结束才释放锁。

### 9.3 GPU 冲突

风险：

- 多个 ServerProfile GPU IDs 有交集。
- 外部用户绕过系统启动训练。

缓解：

- 系统内部用 ResourceLock 控制。
- 启动前检查 `nvidia-smi` 外部进程。
- UI 展示 `external_busy`。

### 9.4 YAML 配置复杂度

风险：

- 可视化字段无法覆盖 LLaMA-Factory 全量参数。
- YAML 编辑后结构化字段丢失。

缓解：

- 保留 `raw_yaml`。
- 可视化只覆盖常用字段。
- 未识别字段原样保留。

### 9.5 凭据安全

风险：

- Jupyter token 泄露。
- 前端可执行任意远程命令。

缓解：

- Token 仅保存在后端。
- 前端只调用业务动作。
- 调试用 `/api/remote/run` 默认关闭。
- 后续加入用户权限。

## 10. 推荐下一步

建议下一步只做 Phase 1：

1. 在项目中新增 `server/`。
2. 把已验证的 Jupyter 长连接队列改造成 `JupyterTerminalExecutor`。
3. 做服务器探测 API。
4. 替换 `ServersPage` mock 连通性检查。

这一步能最小成本验证真实远程执行链路，同时不会过早重构任务系统。
